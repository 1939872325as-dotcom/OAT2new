OAT2new 是一个 Windows 上的阴阳师自动化工具：用 **模板匹配 + OCR** 识别游戏画面，
通过 **PrintWindow 截图 + PostMessage 点击** 在后台操作，按「模式」配置循环执行。
窗口被遮挡也能跑，不占用鼠标键盘。

核心是「配置驱动」：每个副本/玩法对应一组「图片 + 识别规则 + 点击动作 + 流程链」，
程序循环 `截图 → 识别 → 点击 → 等待`，直到完成指定次数。

## ✨ 功能一览

| 分类 | 能力 |
| --- | --- |
| 识别 | 模板匹配 + OCR 双通道；PP-OCRv6；整帧只推理一次；模板与 OCR 并行扫描；模板匹配默认灰度（快约 6 倍，可关） |
| 操作 | 后台截图/点击；区域内随机点击；按图随机等待；按下/移动时序随机 |
| 安全闸 | **出现图片停止点击**（命中条件图本轮不点）；短目标防误点；坐标无效时跳过而非点 (0,0) |
| 流程 | MAA 风格 `next` 任务链；断链自动重扫；超时/重试/连续命中预算；暂停/继续/停止 |
| 配置 | 可视化编辑器；截图添加/替换；OCR 自动命名；图片配置复制粘贴；显示名与后端解耦 |
| 运行 | 多开管理；完全/程序/键鼠三种窗口同步；启动自动提权；免编译热加载 |
| 日志 | 界面单行动态状态行 + 后台明细分流；按天写文件；缓存占用统计与一键清理 |

## 🚀 快速开始

1. 下载打包版：[**OAT2new-v2.3.11.zip**](https://github.com/1939872325as-dotcom/OAT2new/releases/download/OTA2new-v2.3.11/OAT2new-v2.3.11.zip)
   （或到 [Releases](https://github.com/1939872325as-dotcom/OAT2new/releases) 选版本）
2. 解压到任意目录，双击 **`启动OAT2.exe`**（或进入 `app\` 运行 `OAT2.exe`），建议以管理员身份运行
   （游戏常以管理员运行，普通权限会被 UIPI 拒绝后台操作）
3. 选择客户端 → 点「**窗口检测**」确认识别到游戏窗口
4. 选模式、填次数 → 点「**开始挑战**」

> 包内 `app\` 是程序目录：`app\OAT\` 是业务源码，**不要拆包**。本版本是免编译热加载：改 `app\OAT\**.py`，重启程序即生效。
> 识别不到时先看 `app\logs\log_YYYY-MM-DD.log`，界面折叠掉的模板分数、OCR 兜底等明细都在里面。

## 🖱 拟人化点击

固定坐标 + 固定间隔是脚本最明显的特征。OAT2new 把两者都打散：

### 区域内随机点击

**编辑图像配置 → 点击区域设置 → 点击方式**：

| 方式 | 落点 | 适用 |
| --- | --- | --- |
| 点击图片区域（默认） | 识别区域**中间约 2/3** 内均匀随机 | 有稳定图案的按钮 |
| 点击自定义区域 | `[x1, x2, y1, y2]` 两区间内随机 | 位置固定、无稳定图案 |

> 自定义区域是**两个区间**，不是「左, 上, 宽, 高」；`x1==x2 且 y1==y2` 即固定点点击。

### 点击后随机等待

**编辑图像配置 → 点击区域设置 → 点击后随机等待(秒)**，默认 `0.8~5`，按图配置：

- 两个框都留空 → 用默认值，不写进配置
- 只填一个 → 另一个按默认补（填 `2` → `2~5`）
- 写反了 → 自动交换；负数 → 拒绝
- 等待发生在点击之后；**暂停时长不计入**，停止立即中断；每次实际秒数写日志

### 点击时序

按下时长 `200~250ms`、移动→按下间隔 `50~60ms` 随机（原来是固定值）。

> 计算过程、日志示例与调参建议见
> [操作指引 · 随机点击与随机等待](./docs/操作指引-随机点击与随机等待.md)。

## ⛔ 停止点击（出现图片停止点击）

**一句话：点这张图之前，先看画面上有没有「不该点」的条件图；出现了就本轮不点，等几秒再看。**

### 解决什么问题

固定流程最容易出事的时刻，是**弹窗 / 结算 / 公告 / 体力不足提示**突然盖住目标按钮：
程序只认目标图，照样点下去，结果点到弹窗、跳过奖励、误花体力，甚至把流程带偏。

「停止点击」给单张图加了一道**前置闸**：只要指定的条件图出现，这张图本轮就不点。

### 怎么配

1. 打开 **编辑图像配置**（要加闸的那张目标图）
2. 找到 **停止点击设置**，勾选「**出现图片停止点击**」
3. 在 3 个方框里点 **+**，对着游戏窗口框选**条件图**（出现它就不点）
   - 已有图时点击方框 = 重新截图；右键 = 重新截图 / 清除
   - 条件图保存在模式目录的 `stop/` 下（`stop_时间戳.png`），配置里存相对路径
4. 填 **停止时间(秒)**，默认 `5`：命中后本轮等待多久再进入下一轮
5. 保存。**至少要有 1 张条件图**，否则会提示并且不保存

### 运行时怎么判

每次准备执行这张图的动作前：

```
同一帧截图
  ├─ 先比条件图（编辑器最多 3 张，按配置顺序；配置文件可写更多。阈值与这张图的模板阈值一致）
  │    命中任意一张 → 本轮不点，等「停止时间」秒，画面帧作废，按「未命中」处理
  └─ 都没命中 → 正常走点击（模板点击 / OCR 点击 / 坐标点击）
```

几个关键点：

- **优先级最高**：闸在一切点击路径之前，模板、OCR、坐标三种点击都会被拦住
- **不推进流程**：命中时**不更新 `next`、不通知同步器、不计入连续命中**，只是本轮跳过
- **共用一帧**：条件图与模板/OCR 用同一帧识别，不会为了闸多抓一次屏
- **暂停感知**：等待期间暂停，暂停时长不计入；停止挑战立即中断
- **两种引擎都支持**：MAA 管道模式与通用挑战模式都会走这道闸

### 日志长什么样

```
停止条件命中（图 stop_20261118-213000.png 出现），本轮不执行任务 tanshi 的动作，停止 5 秒
```

### 典型用法

| 场景 | 条件图 | 效果 |
| --- | --- | --- |
| 结算/奖励弹窗盖住「挑战」 | 结算面板特征图 | 弹窗在时不点挑战，等它消失 |
| 体力不足提示 | 体力不足图标 | 不空点，等恢复或人工处理 |
| 公告/活动弹窗 | 弹窗标题图 | 避免误点关闭或误触活动 |
| 战斗动画未结束 | 技能特写/加载图 | 等动画播完再点下一步 |

### 注意

- 条件图要**按当前窗口尺寸截**（用编辑器里的截图添加，抓的就是客户区），否则匹配分数不够
- 编辑器给 3 个槽位；配置文件里可以手动写更多，运行时会全部检查
- 条件图文件缺失时该条件不生效（通用挑战模式会告警），不会卡死流程
- 「停止时间」是**本轮等待**，不是暂停程序；填 `0` 表示只跳过本次、不等待

## 🧠 识别与流程

- **双通道识别**：模板匹配负责稳定图案，OCR 负责文字按钮；模板不中时复用同帧 OCR 结果兜底
- **整帧一次 OCR**：一轮内所有配置共用一次全帧推理（帧指纹缓存），不再每张图各跑一次
- **并行扫描**：整帧 OCR 与全部模板 `matchTemplate` 同时进行，按「全局任务 > 流程链下一张 > 其余」+ 置信度择优
- **OCR 引擎池**：CPU / GPU（可选 CUDA）双引擎，按实测时延动态派发，出错自动冷却回 CPU
- **OCR 模型**：PP-OCRv6 det/rec（`app/rapidocr/models/`），小字/艺术字比 v4 稳；缺模型时回落内置 v4 并打日志
- **防误点**：短目标（如「挑战」）命中更长的聊天/横幅文本时判不可信；det 拆行时相邻行拼接后再判；2×2 排版按阅读顺序聚类
- **流程链**：MAA 风格 `next` 串联；等待下一张图时若起点图仍在画面上，判定上一步点击未生效并提前重试；断链打 WARNING 并重置
- **预算**：每任务 `timeout` / `max_retries` / `max_consecutive` 可配，避免死循环

## 🎨 灰度匹配（速度与精度的取舍）

**设置 → 灰度匹配**，默认**开启**。它只作用于「特征匹配」（模板匹配）这条通道；
OCR 走模型推理，完全不受影响。运行中切换立即生效，不用重启。

**实现方式**：灰度转换装在 `cv2.matchTemplate` 这一层统一生效 —— pyscreeze、pyautogui
以及以后新增的任何匹配调用都会自动继承，不需要逐个调用点配置。需要彩色匹配的特例
可以用 `match_util.color_mode()` 临时绕过。
**彩色复核**：灰度命中的最高峰回原彩色图上复核一次，彩色分比灰度分低 0.15 以上就判
「同形异色」（灰按钮撞彩色模板、稀有度边框、元素球），压制该峰继续找次优；真命中与
光度退化（模糊/遮挡）时彩色分≈灰度分，不受影响；等待态零复核开销。
**已知边界**：模板本身低饱和（米白底+深字按钮）时灰度分与彩色分都很高，复核救不了
这种灰状态——用「停止点击」把灰色状态截成条件图解决（彩色模式也同样会命中）。

### 为什么默认开

| 指标 | 彩色 | 灰度 | 提升 |
| --- | --- | --- | --- |
| 单模板全帧匹配（1416×798） | ~142 ms | ~21 ms | 6.8× |
| 10 张模板一轮 | ~1.33 s | ~0.22 s | 6.1× |
| 现有 117 张模板的匹配分数 | — | 一致 | 正/负样本同档 |

三通道合成单通道后 `matchTemplate` 的计算量降到约 1/3，加上内存访问更连续，实测约 6 倍。
同一帧在一轮内会被多个任务复用，灰度图按线程缓存，不会重复转换。

### 什么时候应该关掉

灰度只保留亮度、丢弃色度。如果两个状态**形状和亮度一样、只有颜色不同**，灰度就分不开：

| 场景 | 例子 |
| --- | --- |
| 稀有度 / 品质边框 | 御魂、式神的橙 / 红 / 紫 / 蓝边框 |
| 属性图标 | 火 / 水 / 风 / 雷元素球 |
| 技能状态 | 同图标「可用（彩色）vs 冷却（灰化）」 |
| 按钮状态 | 选中金边 vs 未选中白边 |

要识别这类状态时，把「灰度匹配」关掉改回彩色即可（只影响模板匹配，不影响 OCR）。

### 实测边界

- 亮度 ±15、对比度 ×1.1、色偏、噪声、1px 位移：灰度与彩色分数都 ≥0.99，无差别
- 3px 模糊：0.96；25% 区域遮挡：0.87~0.90
- 2% 缩放：0.736（两种模式相同，属于模板尺寸问题，不是灰度造成的）
- 灰度唯一副作用：负样本分数会轻微抬高（实测最大 +0.10），仍远低于可用阈值

> 结论：现有模板以文字 / 按钮为主（亮度结构占主导），灰度是纯收益；
> 只有「同形异色」的图标类识别才需要彩色。

## 🛠 配置与编辑器

- **截图添加 / 截图替换**：直接框选游戏窗口，`PrintWindow` 后台抓图，1:1 客户区像素；框选位置自动预填「OCR 搜索区域」
- **OCR 搜索区域**：`[x1, x2, y1, y2]`，同页有两处相同文字时只在你框的范围内找
- **自动命名**：新增图片默认用识别到的 OCR 文字命名；模式/子模式目录名自动生成并去重
- **显示名解耦**：界面「名称」只写 `label`，配置键/模板/磁盘文件名仍由文件名派生，改名不断链
- **复制粘贴**：选中图片 `Ctrl+C`、切到另一个模式 `Ctrl+V`，图片与全部配置一起复制
- **配置结构**：`app/OAT/source/<模式>/config.json` + 模板图；停止条件图在 `stop/` 子目录

## 📊 日志与排障

| 现象 | 先看什么 |
| --- | --- |
| 识别不到 | `app/logs/log_*.log` 里的模板最高分/阈值/尺寸；模板是否按当前窗口尺寸截 |
| 点不动 | 是否管理员运行；日志里的「后台点击 (x, y)」坐标是否在客户区内 |
| OCR 不准 | 启动日志 `OCR模型升级`；`app/rapidocr/models/` 是否有 v6 两个 onnx |
| 窗口句柄失效 | 重新点「窗口检测」；日志会提示按标题重找 |
| 更新检查失败 | 未认证访问 GitHub API 有频率限制；本地缓存 1 小时 |

界面只显示一条**动态状态行**（最近识别时间 + 呼吸灯），明细都在后台日志文件里，避免刷屏。

## 💻 源码运行与打包

```bash
git clone https://github.com/1939872325as-dotcom/OAT2new.git
cd OAT2new

# Python 3.12
pip install -r requirements-fixed.txt
python main.py
```

打包用 Nuitka：

```bash
python build_release.py
```

`main.py` 支持**热更新打包**：用 `--nofollow-import-to=OAT` 编译 exe，业务代码留在磁盘，
改 `OAT/**.py` 重启即生效，无需重新编译。
