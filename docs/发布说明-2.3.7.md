# 发布说明 · OTA2new v2.3.7

> 版本：`2.3.7`（`app/OAT/tools/settings.py` → `APP_VERSION`）
> 性质：**性能更新**——模板匹配默认走灰度，实测快约 **6 倍**，识别结果不变

## 一、性能提升（实测）

### 1. 数字

| 场景 | 彩色（2.3.6） | 灰度（2.3.7） | 提升 |
| --- | --- | --- | --- |
| 单模板全帧匹配（1416×798） | 136 ~ 142 ms | 21 ~ 23 ms | **6.2 ~ 6.8×** |
| 10 张模板一轮（串行） | 1.33 s | 0.22 s | **6.1×** |
| 引擎端到端 `find_template` | 136.0 ms | 22.1 ms | **6.2×** |

测试条件：`app/OAT/source/` 下真实模板（最大 235×176）、真实游戏帧 1416×798、
`TM_CCOEFF_NORMED`、单线程。并行扫描下整轮耗时由最慢的一张决定，所以单张快 6 倍 ≈ 整轮快 6 倍。

### 2. 为什么快

- 三通道合成单通道，`matchTemplate` 的计算量降到约 1/3；
- 单通道内存访问更连续，实测比理论 3 倍还多，达到 6 倍左右；
- 同一帧在一轮内被多个任务复用，灰度图按线程缓存只转换一次（模板图不缓存，单张转换仅几十微秒）。

### 3. 结果有没有变

没有。117 张现有模板对比：

| 指标 | 彩色 | 灰度 |
| --- | --- | --- |
| 正样本最低分 | 0.736 | 0.736 |
| 负样本最高分 | 0.345 | 0.364 |
| 可分离度（正 − 负） | 0.390 | 0.371 |

真实帧端到端：同一模板在同一位置给出相同的 `1.0000` 分与相同区域 `(599, 744, 211, 51)`。

## 二、新增设置开关

**设置 → 灰度匹配**，默认开启，运行中切换立即生效（不用重启）。

覆盖 4 条非 OCR 匹配路径：

1. MAA 管道模式 —— `pipeline/recognition_opencv.py`
2. 通用挑战 / pyscreeze —— `tools/OnmyojiAuto.py`
3. `GetDC.find_image_precise` —— `tools/GetDC.py`
4. 绘卷刷分 —— `source/huijuanshuafen/base.py`

## 三、什么时候要关掉

灰度只保留亮度、丢弃色度。如果两个状态**形状和亮度一样、只有颜色不同**，灰度就分不开：

| 场景 | 例子 |
| --- | --- |
| 稀有度 / 品质边框 | 御魂、式神的橙 / 红 / 紫 / 蓝边框 |
| 属性图标 | 火 / 水 / 风 / 雷元素球 |
| 技能状态 | 同图标「可用（彩色）vs 冷却（灰化）」 |
| 按钮状态 | 选中金边 vs 未选中白边 |

现有 117 张模板里没有这类「同形异色」的成对模板，所以默认开启是纯收益；
以后要识别这类图标时，把开关关掉改回彩色即可。

## 四、升级注意

1. **覆盖安装会覆盖配置**：本包含作者全量配置，若你已有自己的 `app/OAT/source/` 与
   `app/OAT/tools/settings.json`，请先备份再合并。
2. 升级后首次启动读到 `"use_grayscale": true`；想改回彩色到设置页关掉即可，**不用重启**。
3. 运行方式与 2.3.6 相同：解压后双击 `启动OAT2.exe`（建议管理员），不要拆包。
4. GPU（可选）：发布包为控制体积未附带 CUDA / cuDNN 运行库，默认走 CPU；
   需要 GPU 时按 [2.3.5 发布说明](./发布说明-2.3.5.md) 自行放置 CUDA 13 / cuDNN 9 运行库。

## 五、验证

- 启动后「设置」页能看到「**灰度匹配**」开关，默认开启；
- 运行任意模式，识别与点击行为与 2.3.6 一致；
- 需要对照时关掉开关，同一画面的模板分数与 2.3.6 完全相同。
