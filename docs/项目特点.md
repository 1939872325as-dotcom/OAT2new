## 一、这是什么

一个 Windows 上的阴阳师自动化工具：通过**计算机视觉**（模板匹配 + OCR）识别游戏画面，
再用**后台消息**方式模拟点击，帮玩家自动刷副本。

核心思路是 **「配置驱动」**：每个副本模式对应一组「图片 + 识别规则 + 点击动作」，
程序循环截图 → 识别 → 点击 → 等待，直到完成指定次数。

它不是靠固定坐标盲点，而是**先看图、再动手** —— 所以窗口大小、界面变化都能自适应（前提是模板是当前版本截的）。

## 二、整体特点

| 特点 | 说明 |
| --- | --- |
| **后台运行** | 用 `PrintWindow` 抓窗口 + `PostMessage` 发点击，**不占用鼠标、窗口被遮挡也能跑**（桌面版/MuMu 均支持） |
| **两种模式引擎** | 老的「通用挑战」（按顺序比对多张图）和新的 **MAA 风格管道**（`next` 串联任务链），后者可写复杂流程 |
| **多副本覆盖** | 魂土、魂王、业原火、觉醒、爬塔（门票/体力）、灵染试炼、御灵、契灵探查、绘卷等 |
| **多窗口同步** | 一个主窗口操作，多个副窗口跟随，支持完全同步 / 程序同步 / 键鼠同步 |
| **拟人化操作** | **区域内随机点击** + **点击随机等待**（本文重点） |
| **可视化配置** | 图形界面里选模式、设次数、编辑每张图的识别/点击参数 |
| **内置截图工具** | **配置截图框选**（本文重点），边玩边截模板，不用另开工具 |
| **免编译热加载** | 业务代码在磁盘上，改 `.py` 重启即生效，**不需要重新打包 exe**（便于自己改逻辑） |

> 「快速上手」见文末。

## 三、重点功能一：区域内随机点击

### 它解决什么问题

如果每次都点在**同一个像素**，点击轨迹在时间轴上就是完全重合的一个点 —— 这是脚本最明显的特征之一。
真实玩家手会抖，每次落点都有几像素差异。

**区域内随机点击 = 每次点击在目标区域内换一个点。**

### 两种方式

在 **编辑图像配置 → 点击区域设置 → 点击方式** 里选：

#### ① 点击图片区域（默认，推荐）

程序先识别出目标在屏幕上的**矩形区域** `(x, y, w, h)`，然后在这个区域的**中间约三分之二**里随机取点：

```
中心点    cx = x + w/2          cy = y + h/2
抖动范围  ± w/3                 ± h/3
实际落点  X ∈ [cx - w/3, cx + w/3]   再夹回区域范围内
          Y ∈ [cy - h/3, cy + h/3]   再夹回区域范围内
```

**举例**：识别到的区域是 `x=600, y=400, w=138, h=61`

| 步骤 | 计算 | 结果 |
| --- | --- | --- |
| 中心 | `600+69` / `400+30` | (669, 430) |
| 抖动 | `138/3=46` / `61/3=20` | ±46 / ±20 |
| **落点范围** | X∈[623, 715]，Y∈[410, 450] | 区域内 92×40 的一块 |

上面的数字是**实测采样 400 次**得到的，不是推算。

> **为什么不整块区域都随机？**
> 因为识别区域往往**比目标按钮大一圈**（模板会把周围背景一起框进去）。
> 若允许点到最边缘，就可能碰到相邻按钮或空白处。收窄到中间 2/3，是「既随机又点得准」的折中。

#### ② 点击自定义区域

自己填一个区域 `[x1, x2, y1, y2]`：

```
X ∈ [x1, x2] 的随机整数
Y ∈ [y1, y2] 的随机整数
```

**注意**：这个格式是**两个区间**，不是「左, 上, 宽, 高」。
填 `[100, 200, 300, 400]` 表示 `X 在 100~200 之间`、`Y 在 300~400 之间`。

> 若 `x1 == x2` 且 `y1 == y2`，就等价于**固定点点击**（没有随机）。
> 需要绝对精确点某一点时用这种写法。

### 一个安全细节

如果**既没有可用的固定区域、又没识别到区域**，程序**不会**去点窗口左上角（`(0,0)`），
而是**跳过这次点击并记一条 error**：

```
无法确定点击坐标（target=matched，固定区域=None/None，识别区域=None），已跳过点击
```

早前版本会静默点 `(0,0)`，表现就是「日志说成功、实际点了个没用的地方」。

## 四、重点功能二：点击随机等待

### 它解决什么问题

如果每次点完都等**同样的秒数**再点下一个，间隔就像节拍器 —— 又一个明显的脚本特征。

**点击随机等待 = 每次点击后，等一个随机时长。**

### 在哪配

**编辑图像配置 → 点击区域设置 → 点击后随机等待(秒)**

```
点击后随机等待(秒):  [0.3] ~ [5.0]
```

**默认 `0.3 ~ 5` 秒，按图配置** —— 每张图可以设成不一样的：

| 图片 | 建议区间 | 原因 |
| --- | --- | --- |
| 普通按钮 | `0.3 ~ 5`（默认） | 常规节奏 |
| 需要等界面响应 | `0.5 ~ 1.5` | 等动画播完 |
| 结算/加载等长驻界面 | `1 ~ 3` | 界面本身就要停留 |

### 填写规则（容错）

| 情况 | 行为 |
| --- | --- |
| **两个框都留空** | 用默认 `0.3~5`，且**不写进配置文件**（保持配置干净） |
| **只填一个** | 另一个按默认补 —— 只填最短 `2`，实际是 `2 ~ 5` |
| **写反了**（`8` 和 `1`） | **自动交换**成 `1 ~ 8`，不报错、不卡住 |
| **填负数** | 拒绝并提示 |

### 执行细节

1. **等待发生在「点击之后」**，不是点击之前。目的是让**下一次识别的时刻**不固定。
2. **暂停时不计入等待时间**。中途暂停挑战，暂停的那段不算在随机等待里，恢复后继续走完剩余时长。
3. **停止挑战立刻中断**等待。
4. **每次实际等待秒数都写进日志**，可事后核对。

### 日志长什么样

挑战开始时先打印默认区间，以及**哪些图单独配过**：

```
点击后随机等待：默认 0.3~5 秒；已单独配置的图：tanshi, jieshu
```

每次点击后：

```
后台点击 (655, 420)
点击后随机等待 2.64 秒（任务 tanshi 区间 1~3）
```

括号里的 **`任务 tanshi 区间 1~3`** 能一眼确认用的是**哪张图**的配置 —— 也就验证了「按图配置」真的生效。

### 一个重要提醒

这是**降低规律性**的手段，**不是加速手段** —— 它会**主动多花时间**（默认平均约 2.65 秒/次），
这是追求稳定挂机的必要成本。

但**不要把等待调到 0 想更快**：界面还没刷新就执行下一步，反而更容易出错、重试更多，**总耗时会更久**。
宁可留一点余量。

## 五、重点功能三：配置截图框选

### 它解决什么问题

模板匹配最容易踩的坑是：**模板是在 A 尺寸下截的，运行时窗口是 B 尺寸** → 分数不够 → 识别失败。

传统做法是「用别的截图工具截屏 → 裁剪 → 存成文件 → 再在软件里选这个文件」，
中间只要窗口尺寸或缩放动过一点，截出来的模板就不对了。

**配置截图框选 = 直接在软件里框选游戏窗口，截出来的尺寸天然就是识别时用的尺寸。**

### 怎么用

**设置页 → 编辑模式和图像**，两个按钮：

| 按钮 | 用途 |
| --- | --- |
| **截图添加** | 框选一块 → 存为**新模板** → 自动弹出图像配置对话框 |
| **截图替换** | 先选中一张已有图 → 框选覆盖它 → **文件名和配置全部不变** |

（也可以用原有的「添加图像 / 替换图片」，从资源管理器挑现成文件。）

### 三个关键设计

**① 图源是「后台抓取的游戏窗口」，不是屏幕截屏**

用的是 `PrintWindow`（优先走 MuMu 后台通道），所以：

- **不打扰游戏** —— 窗口被遮挡也能抓；
- **抓的是窗口客户区（真正的游戏画面区域）**，因此**截出来的像素尺寸 = 识别时用的尺寸**，
  从根上消除「模板尺寸不匹配」。

**② 遮罩贴住游戏窗口，按原始像素 1:1 显示**

不是把画面放大铺满整个屏幕。遮罩正好盖在游戏窗口上、**所见即所得**：

```
拖拽框选要作为模板的区域   ·   1441x812   ·   Esc / 右键取消
```

放大铺满会导致画面发虚，而且看起来像「只显示了部分游戏画面」—— 所以按 1:1 贴住窗口。
（若窗口被系统限制成别的尺寸，才退化为等比缩放居中，保证仍能看全。）

**③ 框选的位置会被自动记录下来**

松手存图后，程序把**框选位置换算成配置格式**，自动预填进「**OCR搜索区域**」：

```
截图添加：shot_20261004-193000.png  138x61  @(300,500)
         来自窗口画面 1441x812  区域[x1,x2,y1,y2]=[300,438,500,561]
```

这正是解决「**一个页面有两处相同文字、总是点错**」的办法 —— **框哪儿就只在哪儿找字**。

同时也会把位置填进「自定义区域」框供参考，但**点击方式仍默认「点击图片区域」**，
不会因为带了坐标就悄悄改成固定坐标点击。

### 两个防呆设计

| 设计 | 作用 |
| --- | --- |
| 遮罩右上角常驻 **「✕ 取消 (Esc)」按钮** | 万一键盘焦点没进入遮罩，也有一个**看得见、点得到**的出口，不会被困住（`Esc` 和右键同样可取消） |
| **截图替换前先备份** | 覆盖前把原图存为 `.bak`，写失败就保留备份、不动原图；写成功再删掉。避免「替换到一半失败、原图也没了」 |

另外，`jpg` 模板替换时会**按目标扩展名重新编码**（`.jpg` 写 JPEG、其余写 PNG）。
早前是直接复制字节，会出现「内容是 PNG、扩展名却是 .jpg」的文件。

## 六、三者如何配合

这三个功能串起来就是一条流畅的「配一次、长期跑」的链路：

```
① 配置截图框选  →  对着当前游戏画面框选目标，模板尺寸天然正确
                    （位置自动记入「OCR搜索区域」，同页相同文字不再点错）
                            ↓
② 区域内随机点击 →  运行时每次在识别区域内换一个点，不再每次都戳同一像素
                            ↓
③ 点击随机等待  →  每次点击后等一个随机时长，间隔不再像节拍器
```

配置成本从「截屏 + 裁剪 + 存文件 + 手填坐标」降到「框一下」，稳定性还更高。

**一句话**：**截得准（截图框选）→ 点得准且不呆板（区域内随机点击）→ 节奏不乱（点击随机等待）**。

## 七、快速上手

1. **下载**打包版：[OTA2new-v234.1.zip](https://github.com/1939872325as-dotcom/OAT2new/releases/download/OTA2new-v234.1/OTA2new-v234.1.zip)
   （或从 [Releases](https://github.com/1939872325as-dotcom/OAT2new/releases) 页面下载）
2. **解压**到任意目录，运行里面的 **`OAT.exe`**（建议**以管理员身份运行**）
3. 选客户端 → 点「**窗口检测**」确认识别到游戏窗口
4. 选模式、设次数 → 点「**开始挑战**」

> ⚠️ 包内 `OAT/` 目录是业务源码，**不要删** —— 本版本是免编译热加载，改磁盘源码即可生效。

**新手建议**：先用新增的「**截图添加**」对着当前游戏画面，把模式里几张关键图**重截一遍**
（尤其是沿用旧版本模板时）—— 因为窗口尺寸语义修正后，旧模板的尺寸可能已经不匹配。

## 八、其它值得一提的改动

除上述三个重点，本项目相对上游还修掉了一批**「静默失败」**类缺陷（日志说成功、实际没动作）：

- **管道模式「显示挑战完成但根本没点」**：三处根因 —— OCR 阈值从未传下去、
  点击前没校验窗口句柄、算不出坐标时静默退回 `(0,0)`。
- **OCR 点错位置**：同页两处相同文字时改为「收集全部候选 → 完全匹配优先 → 置信度最高」；
  并修掉缓存**不含图像内容**导致的「换帧后仍用上一帧坐标」。
- **无效窗口句柄刷屏**：`(1400, 'GetWindowRect', '无效的窗口句柄')` 不再出现。
- **窗口尺寸语义**：原先「客户区 / 外框」混用，导致每次「窗口检测」尺寸都漂移。
- **更新检查**：403 / 解析失败不再静默吞掉更新提示；去掉 `verify=False`。

逐条说明见 [变更明细](./变更明细.md)，完整 diff 见
[CHANGES-vs-upstream.patch](../CHANGES-vs-upstream.patch)。
