# 发布说明 · OTA2new v2.3.5

> 版本：`2.3.5`（`OAT/tools/settings.py` → `APP_VERSION`）
> 基线：上游 `main`（v2.3.4）
> 性质：**免编译热更新**——`OAT/` 是业务源码，改磁盘源码 + 重启即生效。

## 一、本次重点（相对 2.3.4.2）

### 1. OCR：更快、更准、更省 CPU

| 改动 | 说明 |
| --- | --- |
| 双引擎池 `utils/OCREnginePool.py` | CPU + GPU（ONNX Runtime 1.30，CUDA/DirectML）各一条工作线程；按实测时延（在途数 × EWMA）动态派发，GPU 快就多担、出错自动冷却回 CPU |
| 一帧只识别一次 | 新增 `OCRService.recognize_frame_items()`：整帧 OCR 一次（帧指纹缓存），一轮内所有配置共用；原来每个配置各跑一次全帧推理 |
| 并行扫描 | `runner._process_round()`：整帧 OCR 与全部模板 `matchTemplate` 同时进行，按「全局任务 > 流程链下一张 > 其余」+ 置信度择优点击 |
| 模型升级 | det/rec 切到 **PP-OCRv6**；自动填文字支持多变异择优（原始 / 2x 放大 / 提对比度）与多行拼接（2x2 排版按钮可拼出完整词） |
| 阈值实时生效 | 设置页「识别阈值」滑块对**正在跑的**任务立即作用（引擎每轮现读设置） |
| Unicode 图像读写 | 新增 `utils/image_io.py`：修复中文文件名下 `cv2.imread` 返回 None 的坑（模板加载 / OCR / 截图读取全部走它） |

### 2. 识别准确性

- **短目标防误点**：目标文字（如「挑战」）在识别文本里只是子串时会命中聊天/系统横幅。规则：命中文本比目标长出 3 字以上判不可信（单行候选、相邻行拼接、旧裁剪路径三处统一）。
- **相邻行拼接匹配**：det 把多字按钮拆成多行时（`伤`+`害排名`），把相邻行拼起来再判子串，命中用并集框点击。
- **行聚类阅读顺序**：2x2 排版（召 唤 / 鬼 王）不再出现「召唤王鬼」这种错序。
- **流程链等待期起点图复检**：等下一张图时若起点图仍在画面上，判定上一步点击未生效并提前重试，不再空等 15 秒。
- **点击时序随机化**：按下 200~250ms、指针移动间隔 50~60ms（原来是固定 200ms / 50ms）。

### 3. 编辑器与显示名

- **显示名与后端解耦**：图像「名称」只写 `label`（展示用），配置键 / `template` / 磁盘文件名一律由文件名派生，改显示名不再改后端结构；磁盘文件名保持 ASCII。
- **自动命名**：模式/子模式目录名自动生成（重名加序号，大小写不敏感）；新增图片的名称默认用识别到的 OCR 文字。
- **截图替换**也会按识别文字更新显示名与 OCR 目标文字（配置文件不动名）。

### 4. 日志与交互

- **前后端分流**：模板分数、OCR 兜底等明细只写后台文件（`logs/log_YYYY-MM-DD.log`）；界面只保留一条**动态「等待命中」状态行**（原地刷新最近识别时间 + 黄色渐变呼吸灯），命中即消失。
- 暂停按钮增加「暂停中…」确认轮询，避免连点把刚发出的暂停又切回继续。

## 二、升级注意事项

1. **OCR 模型**：`<程序目录>/rapidocr/models/` 需要存在 `PP-OCRv6_det_small.onnx`、`PP-OCRv6_rec_small.onnx`（缺省时启动日志会打印 `OCR模型升级: v6 模型未找到…`，此时回落到内置 v4，小字/艺术字识别能力下降）。
2. **GPU 加速（可选）**：`onnxruntime/capi/` 换成官方 1.30.0 四件套 + 目录内准备 CUDA 13 / cuDNN 9 运行库即可启用 `gpu(cuda)`；没有 GPU 环境时自动单 CPU，不影响功能。
3. **配置兼容**：旧 `config.json` 不需要手工迁移；显示名（`label`）为空时自动回退为空文件名。
4. **热更新**：覆盖 `OAT/` 源码后**重启程序**（进程启动时一次性 import，运行中不热载）。
