# 发布说明 · OTA2new v2.3.9

> 版本：`2.3.9`（`app/OAT/tools/settings.py` → `APP_VERSION`）
> 性质：**机制调整**——灰度从「逐调用点接线」改为「在 `cv2.matchTemplate` 层统一安装」

## 一、为什么改

2.3.7 / 2.3.8 是给每个匹配调用点单独加灰度参数。这种做法有两个问题：

1. **会漏**：2.3.7 就漏了 `GetDC._find_image_pyscreeze`，而那正是「后台运行 + 识别模式 = pyscreeze」走的路；
2. **不可继承**：以后新增任何匹配调用（或第三方库内部调用）都得再配一次，否则静默走彩色。

2.3.9 把灰度装到 `cv2.matchTemplate` 这一层：非 OCR 的识别最终都落到这个函数
（pyscreeze / pyautogui 内部也是它），装一次，所有现有和未来的调用自动继承。

## 二、现在的机制

- `OAT/tools/match_util.py` 的 `install_global_patch()` 在 `OAT/tools/__init__.py` 导入时执行一次；
- 补丁只做一件事：`USE_GRAYSCALE` 打开时，把 3/4 通道的 `image` / `templ` / `mask` 转成单通道再调用原函数；
- 整帧灰度图按线程缓存（同一帧一轮内多个任务复用只转一次）；
- **OCR 不经过 `matchTemplate`**，走模型推理，完全不受影响；
- 需要彩色匹配的特例：`with match_util.color_mode(): cv2.matchTemplate(...)`。

## 三、覆盖范围

不再依赖逐个调用点配置，全部自动覆盖：

| 场景 | 路径 |
| --- | --- |
| MAA 管道（斗技等） | `pipeline/recognition_opencv.find_template` |
| 通用挑战 · 前台 | `OnmyojiAuto.find_img` → `pyautogui.locateOnScreen` → pyscreeze |
| 通用挑战 · 后台 + 识别模式 = opencv | `GetDC._find_image_opencv` |
| 通用挑战 · 后台 + 识别模式 = pyscreeze | `GetDC._find_image_pyscreeze` |
| 绘卷刷分 | `source/huijuanshuafen/base.py` |
| 以后新增的匹配调用 | 自动继承 |

## 四、实测（与 2.3.8 一致）

| 场景 | 彩色 | 灰度 | 提升 |
| --- | --- | --- | --- |
| 直接 `cv2.matchTemplate`（1416×798） | 130.5 ms | 18.8 ms | **6.9×** |
| 引擎端到端 `find_template` | 131.6 ms | 21.7 ms | **6.1×** |
| `pyscreeze.locate`（不传 grayscale） | 144.4 ms | 33.4 ms | **4.3×** |

分数与坐标完全一致（`1.0000` @ `(599, 744)`）。OCR 实测仍能正常识别
（`点击屏幕继续`），开关对 OCR 无影响。

## 五、升级注意

- 从 2.3.8 升级：覆盖 `app/OAT/tools/match_util.py` 与 `app/OAT/tools/__init__.py`，重启程序即可；
- 从 2.3.7 及更早：按 2.3.7 的说明覆盖 `app/OAT/`（先备份自己的 `source/` 与 `settings.json`）；
- 开关仍是「**设置 → 灰度匹配**」，默认开启，运行中切换立即生效；
- 需要区分「同形异色」（稀有度边框、元素球、技能可用/冷却）时关掉改回彩色，详见
  [2.3.7 发布说明](./发布说明-2.3.7.md)。
