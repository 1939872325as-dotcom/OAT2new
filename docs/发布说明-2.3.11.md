# 发布说明 · OTA2new v2.3.11

> 版本：`2.3.11`（`app/OAT/tools/settings.py` → `APP_VERSION`）
> 性质：**节奏修复**——消除「偶发性不识别」里的两处真等待 + 让彩色复核可排查

## 一、这次修的三件事

### 1. 链等待不再干等 15 秒（通用挑战模式）

实测日志（结界突破，11:23-11:33）：点完结界后列表正在刷新，点击落空，
next 链（勋章结界 → 进攻）**只盯「进攻」干等 15 秒**才超时回全扫描，
一天出现 3 次（11:23:46 / 11:26:53 / 11:30:42），每次白等 ~16s。

现在：链等待超过 **3 秒**就复检「上一张图」（next_image 指向当前目标的那批图）——
它还在画面上就说明上一步点击没生效，重置流程重新处理，不再死等。
同一场景仿真对比：**17.7s → 4.0s**（15s 超时 + 重扫 → 3s 复检命中 + 重试）。

### 2. OCR 引擎挂死的等待 60s → 20s

实测 11:01:04 一次「OCR引擎推理超时(60s)，重新派发」：引擎偶发挂死时要白等 60s。
整帧 OCR 实测 0.15~0.5s，20s 已是几十倍余量——挂死时更快换道重试。

### 3. 彩色复核不再静默

2.3.10 的彩色复核否决是静默的，出现「偶发性不识别」时无法排查。
现在**每次否决都写后台日志**（前端不显示）：
`彩色复核否决：灰度分 0.914 @(700,300) 彩色分 0.736（差 0.178 ≥ 0.15），判同形异色…`
以后再遇到不识别，直接在 `app/logs/log_*.log` 里搜「彩色复核否决」就能看到是不是复核误杀。

## 二、日志怎么读（结界突破为例）

| 日志现象 | 含义 |
| --- | --- |
| 两个事件之间静默 14~27s | 战斗在进行（进攻→战斗→结算），期间没有可点的图，正常 |
| `image 已连续出现2次` | 胜利结算有两个奖励弹窗、连点两张，正常计数提示（到 5 次才会停） |
| `识别超时：jingong 在 15 秒内未找到` | 点击落空 + 旧版干等 15s，**本版已改为 3s 复检重试** |
| `等待「jingong」期间画面仍显示「ling_xunzang」` | 新复检生效的提示：上一步点击没生效，已重置流程 |
| `彩色复核否决：…`（后台日志） | 灰度命中但颜色对不上，被复核层拦下（同形异色保护） |
