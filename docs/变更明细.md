## 二、稳定性修复

### 2.1 `OAT/tools/WindowChecker.py` —— 每轮刷屏的无效句柄异常

**症状**：运行日志里反复出现
`pywintypes.error: (1400, 'GetWindowRect', '无效的窗口句柄。')`，并连带 `GetDC` 的
`BitBlt`/`PrintWindow` 全链路失败（「所有捕获方法失败」）。

**原因**：`get_window_info` 只用 `if hwnd:` 判真值、**从不校验句柄有效性**；而
`main_window.window_detection` 是定时器回调，每轮拿着过期句柄去 `GetWindowRect`。

**修复**：

- 新增 `_resolve_hwnd()`：缓存句柄先用 `win32gui.IsWindow()` 校验，失效则丢弃并按标题重新 `FindWindow`。
- `get_window_info()` / `get_client_info()`：`GetWindowRect` / `GetClientRect` 包
  `except pywintypes.error`，窗口消失时返回 `None` 而**不再抛异常**。

### 2.2 `OAT/app/main_window.py`

- `window_detection()` 整体包 `try/except`，回调异常不再逃逸（兜底；真正的修正在 2.1）。
- 清理缓存后刷新卡片上的占用体积。
- `logger.warn` → `logger.warning`（Py3 已废弃 `warn`）。

### 2.3 `OAT/source/huijuanshuafen/*`

- `base.py`：`find_img_on()` 加空截图保护（截图失败直接返回，不再 `shot.shape` 报 `AttributeError`）。
- `explore.py` / `huijuan.py`：k28 使用**显式阈值**（原用引擎默认 0.90，而 `base.py` 注释写明实测 0.897 会漏检）。
- `huijuan.py`：接住 `common_challenge(...)` 的返回值，突破阶段被停止/失败时**不再白等 5 分钟收尾**。
- 三个文件 `logger.warn` → `logger.warning`。

### 2.4 `OAT/source/__init__.py`

- 新增 `_notify_mode_error()`：模式无法启动时**弹 `warning_box` 并列出可用模式**。
  原来只写一条 ERROR 日志就 `return`，界面表现是「点了开始没反应」，只能去翻日志。
- `folder_info.get(sub_mode, folder_info['default'])` → 用 `or` 链兜底，字典模式缺 `default` 键时不再 `KeyError`。

## 三、OCR 点错位置（同页两处相同文字）

**症状**：一个界面里有两处相同文字（比如两个「挑战」），程序点了另一个，位置和预期不同。

**根因**在 `OAT/tools/OCRManager.py::find_text_offline`，三个缺陷叠加：

1. **命中第一个就返回**——不收集全部候选，于是「两个相同文字」时必然取 OCR 输出顺序里的第一个
   （通常自上而下），你要的那个在下面就被跳过。
2. **`confidence_threshold` 完全不参与判定**——它只出现在 `if debug:` 分支里打印清单，
   而且 `perform_action → find_text_ocr → find_text` 这条链**根本没把它传下去**。
3. **子串匹配**（`in` 而非相等）——找「挑战」会同时命中「挑战次数」；找「确认」会命中标题「确认退出否则吗」。

**修复**：

- `OCRManager.find_text_offline()`：新增 `region` 参数；匹配改为
  **收集全部候选 → 完全相等优先 → 达阈值者优先 → 置信度最高者**（并列时保留 OCR 原始顺序，结果可复现）。
  命中多处时把**每一处的文字/置信度/坐标**写进日志。
- `OCRService.find_text()`：`confidence_threshold` / `region` 真正透传。
- **`OCRService` 缓存键缺陷**：原来对 numpy 图固定用 `f"image:{target_text}"`，**不含图像内容** ——
  换了一帧也会命中旧结果，直接返回上一帧坐标（同样表现为点错位置）。改为按 **64×64 降采样指纹**做键；
  拿不到指纹就不缓存。
- `OnmyojiAuto.perform_action()`：新增 `ocr_region` / `ocr_confidence_threshold`；
  `find_text_ocr()` 先算好「截图坐标→客户区坐标」的偏移 `dy`，再把客户区描述的 `ocr_region`
  换算成截图坐标后裁剪。
- `common_challenge.py`：从 config 读 `ocr_region` 并在两处调用点传下去。
- `edit_mode_and_img.py`：`ImageConfigDialog` 新增**「OCR搜索区域」**输入框（留空 = 全窗口）。
- `pipeline` 侧同步打通（见 [4.2](#42-ocr_region-在管道模式下完全无效)）。

> ⚠️ **坐标语义**：`click_area` / `ocr_region` 都是 **`[x1, x2, y1, y2]`（两个区间）**，
> 不是官方说明里的 `[左, 上, 宽, 高]`。依据是 `OnmyojiAuto.py` 里的 `x1, x2, y1, y2 = click_area`。

```json
{
  "ocr_enabled": true,
  "ocr_target_text": "挑战",
  "ocr_region": [900, 1280, 500, 700],
  "ocr_confidence_threshold": 0.8
}
```

## 四、MAA 管道模式「显示成功但没点击」

**症状**：自己写的 pipeline 模式（如「最新版本活动/PVE」）显示「挑战完成」，但游戏里**根本没点**；
日志里 `匹配到: xxx (置信度: 0.00)`；同一张图被反复命中，中间夹一次「识别超时」。

核实为**5 个独立缺陷叠加**：

### 4.1 三处静默失败

1. **`find_text` 的 `confidence` 参数从未使用**，返回时也**不填 `confidence`**
   → 日志必然 `0.00`，且 pipeline 路径下 `ocr_confidence` **完全失效**。
   *已修*：真传阈值 + 回填真实置信度；文字框退化（宽或高为 0）时判未匹配并说明原因。
2. **`_click_postmessage` 没有 `IsWindow` 校验**（而 `_swipe_postmessage` 有）
   → 句柄失效时 `PostMessage` 静默失败，表现为「日志说成功但没点」。*已修*：加校验 + 明确报错。
3. **`_resolve_click_coords` 在既无固定区域、又无识别区域时静默返回 `(0,0)`**
   → 点到窗口左上角。*已修*：返回 `None`、记 error 并**跳过点击**。

### 4.2 `ocr_region` 在管道模式下完全无效

`ocr_region` 此前只接到旧引擎（`common_challenge` + `OnmyojiAuto`），
**pipeline 侧一行都没有** —— 在管道模式里这个配置填了等于没填。整条链补齐：

| 位置 | 原来 | 现在 |
| --- | --- | --- |
| `task_definition.py` | 不解析 `ocr_region` | 解析成 `Task.ocr_region` |
| `runner.py` | OCR 调用不传区域 | 传 `region=task.ocr_region` 并打日志 |
| `recognition_opencv.find_text` | 签名没有 region | 新增 `region`，客户区坐标→截图坐标换算（处理标题栏偏移） |
| `edit_mode_and_img.py` | 正/反向转换都丢 `ocr_region` | 双向保留，保存/重开不丢 |

### 4.3 主循环计数取错任务

`_process_next_task()` 成功后写的是 `task = self._task_map[self.current_next]`，
但此时 `current_next` 已被 `_match_and_execute` 改成**它的 next** 了 → ①`is_start` 判在错的任务上；
②当 `next` 为空时 `self._task_map[None]` **`KeyError`，直接把整个挑战打成「致命错误」**。
*已修*：统一取 `self._get_last_matched()`。

### 4.4 `_resolve_click_coords` 被重复定义（死代码）

`runner.py` 里该方法**定义了两次**。Python 后定义者覆盖前者，于是修复版成为**死代码**，
实际生效的是会静默返回 `(0,0)` 的旧版。*已修*：删除重复定义，只保留一份。

### 4.5 新增直指病因的告警

若某任务的 `next` 曾超时未出现、之后**它自己又匹配到**，说明上一步的点击没生效 ——
会明确打一条 warning，而不是让你对着一串「还剩N次挑战」猜。

### 关键日志（以前完全无声的节点现在都会打出来）

| 以前 | 现在会打 |
| --- | --- |
| 模板没匹配上，静默退到 OCR | `模板未达阈值: xxx.jpg 最高分 0.812 < 阈值 0.950（最佳位置 x=… y=…，模板 138x61，截图 1138x672）` + `模板未匹配，改用 OCR 兜底：…` |
| OCR 命中的是「更长的文字块」（子串匹配） | `注意：OCR 目标是 '退治'，实际命中的是更长的文字块 '妖怪退治'（子串匹配），命中区域 (…)。若这不是你要点的位置，请把 OCR 目标文字改成完整文字，或用「OCR搜索区域」限定范围` |
| 点击没送达 / 坐标算不出来 | `窗口句柄无效（hwnd=…），消息未发送` / `无法确定点击坐标（…），已跳过点击` |

这三条正好对应一个真实案例：模板是在别的窗口尺寸下截的 → 分数不够 → 退到 OCR →
OCR 按子串命中了页面标题「妖怪退治」而不是右下角按钮「退治」→ 点了标题，什么都不发生。
**旧版本从头到尾一句提示都没有。**

### 4.6 `common_challenge.py`（旧引擎，同类缺陷）

- **删掉跨图共享的 `retry_count`**：原来是全局的，且对**任何**图片命中都自增；一旦某张图触发过
  「连续 2 次」，之后任意 5 次匹配就会把整个挑战判成卡死并 `return False`——而那张图其实早就不卡了。
  现改为由「同一张图的连续命中次数」推导。
- **修掉引用未定义变量**：`if current_next_image != key:` 里的 `key` 只存在于另一个分支的循环中
  （靠循环变量泄漏），首次进入会 `NameError`，而外层是裸的 `except Exception: pass`，
  导致「切图即重置计数」这段逻辑静默失效。统一改用显式的 `matched_key`。
- 新增 `_build_recognition_order()`，**真正读取 `recognition_order`**。此前该字段没有任何代码读取，
  识别顺序实际退化成 JSON 键的书写顺序。
- 两处 `except Exception: pass` 改为记录 warning —— 正是这类裸吞异常让上面两个 bug 藏了这么久。

## 五、窗口尺寸语义修复（行为变更）

**症状**：每点一次「窗口检测」，报出的尺寸都不一样
（1152×679 → 1427×834 → 1404×821 → 1427×834），看起来像「同一件事有两种尺寸格式」。

**结论**：

1. **日志那两行报的是同一个东西——窗口外框**，却标成了「客户端大小」。
   `OnmyojiAuto.py` 的 `self.area = self.get_window_rect()`，而 `get_window_rect()` 与
   `WindowChecker.get_window_info()` **都用 `GetWindowRect`**，拿到的是含标题栏/边框的外框尺寸。
   **真正的客户区（游戏画面）从来没有被打印过。**
2. **`resize_window` 把「客户区目标」当「外框尺寸」用了**：
   `SetWindowPos(hwnd, …, 1404, 834)` 设的是**外框**。所以客户区永远比目标小一截，
   而 `connect_all` 又拿**外框**去和**客户区目标**比 → **永不相等** → 每次点都重调一遍，数字随之漂移。
3. **调整后立即复测会读到旧值**：窗口尺寸变化要几毫秒到几百毫秒才生效。

**修复**：

- `resize_window()` 改按**客户区**语义工作：用 `AdjustWindowRectEx` 把目标客户区尺寸换算成外框尺寸，
  再交给 `SetWindowPos`；换算失败才退回旧行为（并明确警告客户区会偏小）。
- `connect_all()` 改为**按客户区比较与报告**，调整后**轮询等待生效**（最多 2 秒）再复测。
- 新增 `log_size_pair()`：**外框和客户区两个尺寸都打印**，并注明「模板图与截图都以【客户区】为准」。
- `main_window.start_sync()` 同步流程里也把 `get_window_info()` 换成 `get_client_info()`。

> ⚠️ **行为变更**：修好之后「客户区」会真的等于配置里的 1404×834；而旧版是「外框 = 1404×834」，
> 客户区实际约 1388×794。**所以升级后，以前按旧尺寸截的模板都要按新的客户区重截。**

## 六、更新检查

`OAT/config/check_update.py`：

- 加 **1 小时本地缓存**（`config/update_cache.json`）：未认证访问 `api.github.com` 只有 60 次/小时配额，
  原来每次启动都请求，开关几次程序就 403 rate limit。
- 403 / 解析失败降级为 **warning** 并回退缓存；新增 `last_error`，让「检查失败」与「已是最新」可区分
  （原来都返回 `False`，用户永远收不到更新提示）。
- `except KeyError`（永远进不来）改为显式捕获 `json.JSONDecodeError`，并**放在
  `RequestException` 之前**——`requests` 的 `JSONDecodeError` 同时继承这两个基类，顺序放错会被前者吃掉。
- `split_version` 健壮化：`OAT-v2.3.3-beta1` 这类不再抛 `ValueError`。
- 去掉 `verify=False` 和 `InsecureRequestWarning` 抑制。**自更新会下载并执行 zip，
  走未校验的 TLS 是供应链风险。**

`OAT/config/update_manager.py`：

- 去掉 `verify=False`（×3，两处 HEAD + 一处流式下载）与对应的 `disable_warnings`。
- `logger.warn` → `logger.warning`（×4）。

## 七、新增功能

### 7.1 飞书式框选截图 — `OAT/tools/region_capture.py`（新增）

- 遮罩**贴住游戏窗口、按原始像素 1:1 显示**（不放大铺满全屏，避免画面发虚、看起来「只显示了部分游戏画面」）。
- 图源是**后台抓取的窗口客户区**（`PrintWindow`，MuMu 后台通道优先），
  因此**截出来的尺寸就是识别时用的客户区尺寸**，从根上避免模板尺寸不匹配。
- 坐标按比例还原到原图坐标后再裁剪。
- 安全网：右上角常驻「✕ 取消」按钮 + `Esc` / 右键取消。
- 结果通过宿主对象回传（遮罩开了 `WA_DeleteOnClose`，关闭后 C++ 对象已销毁，
  再去读它的属性会抛 `RuntimeError` 把选好的框丢掉）。

配套在 `edit_mode_and_img.py` 新增两个按钮：

| 按钮 | 行为 |
| --- | --- |
| **截图添加** | 框选 → 存为新模板 → 弹出图像配置对话框 |
| **截图替换** | 选中一张图 → 框选 → **覆盖它**，文件名与 `config.json` 配置全部不变 |

两个都会把**框选位置自动预填进「OCR搜索区域」**（框哪儿就只在哪儿找字），
正是「同页两处相同文字」的解法。点击方式仍默认「点击图片区域」，
不会因为带了 `click_area` 就悄悄切成固定坐标点击。

### 7.2 「清理缓存」显示占用体积 — `OAT/utils/cache_utils.py`（新增）

- 设置页卡片显示：`清理截图画廊和日志文件｜当前占用 74.6 KB（日志文件 74.6 KB）`，**分项列出**有内容的部分。
- 打开设置页时重算、清理完成后立刻刷新。
- **路径与真正删除的目标完全一致**（同一个项目根推导、同一批目标），
  否则「显示的数字」和「清掉的东西」对不上，比不显示更误导。

### 7.3 按图配置的「点击后随机等待」

- 位置：**编辑图像配置 → 点击区域设置 → 点击后随机等待(秒)**，如 `[0.3] ~ [5.0]`。
- 留空 = 用默认 0.3~5 秒且**不写该字段**；只填一个则另一个按默认补；写反了自动交换。
- 每张图独立生效；日志会带上任务名与实际秒数：
  `点击后随机等待 1.12 秒（任务 tanshi 区间 1~3）`。
- 用 `pause_aware_sleep` 等待：**暂停时长不计入**，点停止立即中断。

### 7.4 配置健壮性

- `_normalize_area()` / `_normalize_wait()`：同时兼容 `list`（config.json 里存的）与 `str`（GUI 输入框里的）。
  **只认 str 会导致从配置读出的 list 被当成非法而静默丢弃。**
- `_image_paths_to_pipeline_task` / `_pipeline_task_to_image_paths` 双向保留
  `ocr_region`、`click_wait_min/max`，否则保存一次就丢。

## 八、打包与运行

### 8.1 `main.py` 热更新启动器

冻结（Nuitka `--standalone`）运行时，**冻结导入器在 `sys.meta_path` 里优先于 `sys.path`**，
所以磁盘上的 `.py` 会被忽略。本仓库的 `main.py` 在冻结时把「exe 同目录」放进 `sys.path` 最前，
配合 `--nofollow-import-to=OAT` 编译，业务代码（`OAT/`）留在磁盘上，**改动后无需重新编译**。

### 8.2 `_nuitka_deps.py`（新增）

把第三方导入集中放在一个**永不被调用**的函数里，供热更新打包时收集依赖；
顶层直接导入会让 Nuitka 编译产物在启动时崩溃。

### 8.3 依赖
