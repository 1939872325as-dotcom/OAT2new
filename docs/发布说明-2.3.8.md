# 发布说明 · OTA2new v2.3.8

> 版本：`2.3.8`（`app/OAT/tools/settings.py` → `APP_VERSION`）
> 性质：**补丁**——补全灰度覆盖：2.3.7 漏了「后台运行 + 识别模式 = pyscreeze」这一支

## 一、修了什么

2.3.7 把模板匹配切到灰度，但只接了 OpenCV 那条分支。
`GetDC._find_image_pyscreeze()` 仍然走彩色 —— 而**「后台运行模式 + 识别模式 = pyscreeze」**
（通用挑战 / 契灵探查的常见组合）恰好走的就是这一支，这部分场景没有拿到提速。

本版把该分支也接上同一个灰度开关。

## 二、现在的覆盖范围

| 场景 | 代码路径 | 灰度 |
| --- | --- | --- |
| MAA 管道（斗技等） | `pipeline/recognition_opencv.find_template` | ✅ |
| 通用挑战 · 前台 | `OnmyojiAuto.find_img` → `pyautogui.locateOnScreen` | ✅ |
| 通用挑战 · 后台 + 识别模式 = opencv | `GetDC._find_image_opencv` | ✅ |
| 通用挑战 · 后台 + 识别模式 = pyscreeze | `GetDC._find_image_pyscreeze` | ✅ 本版补上 |
| 绘卷刷分（`find_img` / `find_img_on` / `k28_score_on`） | `source/huijuanshuafen/base.py` | ✅ |
| OCR | — | 不适用（不受开关影响） |

> 判断方法：只要识别走的是 `cv2.matchTemplate` 或 `pyscreeze.locate`，就受「设置 → 灰度匹配」控制；
> 走 OCR 的文字识别不受影响。

## 三、实测

`GetDC._find_image_pyscreeze`，1416×798 全帧、211×51 模板：

| 模式 | 耗时 | 返回坐标 |
| --- | --- | --- |
| 彩色 | 144.4 ms | ((599, 810), (744, 795)) |
| 灰度 | 33.4 ms | ((599, 810), (744, 795)) |

**4.3×**，结果完全一致。比纯 OpenCV 路径的 6× 略低，因为这一支每次都要把 PIL 图转成
numpy 再转灰度，多了一次整帧转换。

## 四、升级注意

- 从 2.3.7 升级：只需覆盖 `app/OAT/tools/GetDC.py`，重启程序即可。
- 从 2.3.6 及更早升级：按 2.3.7 的说明（覆盖 `app/OAT/`，先备份自己的 `source/` 与 `settings.json`）。
- 灰度开关仍是「**设置 → 灰度匹配**」，默认开启，运行中切换立即生效。
- 需要区分「同形异色」（稀有度边框、元素球、技能可用/冷却）时关掉改回彩色，详见
  [2.3.7 发布说明](./发布说明-2.3.7.md)。
