# 发布说明 · OTA2new v2.3.10

> 版本：`2.3.10`（`app/OAT/tools/settings.py` → `APP_VERSION`）
> 性质：**识别正确性更新**——灰度层新增「彩色复核」，挡住「同形异色」误命中

## 一、修了什么

灰度匹配有个已知弱点：**形状相同、只有颜色不同的两个状态，灰度分不开**。
典型场景就是组队 lobby——「挑战」按钮没人进入时是灰色、有人进入才变彩色；
如果模板截的是彩色状态，灰度模式下灰色按钮也会被识别到并点击。

2.3.10 在灰度层后面加了一道**彩色复核**：

```
灰度搜索命中（分数 ≥0.65）
  └─ 回原彩色图取同位置小窗，再算一次彩色分
       ├─ 彩色分 ≈ 灰度分（差 <0.15）→ 可信，正常返回
       └─ 彩色分比灰度分低 0.15 以上 → 判「同形异色」，压制该峰，继续找次优
```

等待态（灰度分 <0.65）**零复核开销**；有命中时复核只做一次模板大小的小相关（约 1ms）。

## 二、实测

### 1. 高饱和模板（福袋，chroma/luma=1.18）：灰色状态贴回画面

| 模式 | 最高分 | 结论 |
| --- | --- | --- |
| 2.3.9 灰度 | 0.914 | 阈值 0.9 时**误命中** |
| 2.3.9 彩色 | 0.736 | 阈值 0.9 时不中 |
| **2.3.10 灰度+复核** | **0.398（峰被压制）** | 任何阈值都不中 ✅ |

灰+彩两个状态同时在画面上时，2.3.10 正确命中**彩色**那个（1.000），灰色的被压制。

### 2. 正常识别不受影响

| 模板 | 分数 | 耗时 |
| --- | --- | --- |
| 福袋（235×176） | 1.000 @(572,510) | 28.8 ms（复核开销 ~1ms） |
| 点击屏幕继续（211×51） | 1.000 @(599,744) | 20.6 ms |
| pyscreeze 路径 | 正常命中；灰状态帧返回 None | — |

灰度提速仍然保留（对比彩色 ~142ms/张）。

## 三、已知边界（重要）

模板**本身低饱和**（米白底 + 深色字，比如「挑战 ×12」这种按钮）时，彩色通道
本来就不携带区分信息——实测把按钮去色贴回画面：

| 模式 | 灰色状态得分 |
| --- | --- |
| 灰度 | 0.979 |
| **彩色（2.3.6 就是这样）** | **0.961** |

彩色复核救不了这种「灰状态」（彩色分 ≈ 灰度分，复核条件不成立），**彩色模式
同样会命中**——这不是灰度引入的回归。这类场景请用项目自带的「**停止点击**」：

1. 把**灰色状态**的按钮截成条件图（编辑图像配置 → 停止点击设置 → +）；
2. 挂到彩色模板的「出现图片停止点击」上；
3. 灰按钮一出现，本轮就不点、等 N 秒再试——这正是它设计出来的用途。

## 四、机制速览（2.3.9 起）

灰度转换装在 `cv2.matchTemplate` 这一层（`OAT/tools/match_util.py` 的
`install_global_patch()`，包导入时执行），所有特征匹配（含 pyscreeze / pyautogui
内部调用）自动继承；OCR 走模型推理，不经过这里。彩色复核是同一层的第二道工序。
需要完全绕过的特例：`with match_util.color_mode(): ...`。

## 五、升级注意

- 从 2.3.9 升级：只需覆盖 `app/OAT/tools/match_util.py`，重启程序；
- 从 2.3.7/2.3.8：先按 2.3.9 说明覆盖 `app/OAT/`（2.3.9 还移除了逐点接线）；
- 开关仍是「设置 → 灰度匹配」，默认开启，运行中切换立即生效；
- 组队等待类流程建议同时配置「停止点击」，对灰色/彩色都保险。
