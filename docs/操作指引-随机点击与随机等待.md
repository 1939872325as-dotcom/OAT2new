# 操作指引 · 随机点击与随机等待

> 这两个功能决定「点得准不准」和「像不像人在操作」，是使用中体感最明显的两项。
> 本文讲清楚：**在哪配、默认值是多少、实际点击/等待是怎么算出来的、怎么看日志确认生效**。

## 一、为什么需要这两个功能

**固定坐标 + 固定间隔**是脚本最容易被识别的特征：

- 每次都点在**同一个像素**上 → 点击轨迹在时间轴上是完全重合的点；
- 点完固定等 1.0 秒再点下一个 → 间隔像节拍器一样精确。

真实玩家不会这样：手会抖、点偏几像素，反应快慢也不一样。

所以：

| 功能 | 解决什么 |
| --- | --- |
| **随机点击** | 每次点击在目标**区域内**取一个随机点，不再每次都命中同一个像素 |
| **随机等待** | 每次点击后等一个**随机时长**，间隔不再是固定节拍 |

> 注意：这两个是「降低规律性」的手段，**不是**加速手段。尤其随机等待会**主动多花时间**，
> 这是设计如此 —— 追求稳定挂机时它是必要的成本。

## 二、随机点击

### 2.1 点击坐标是怎么决定的

点击方式有两种（在**编辑图像配置 → 点击区域设置 → 点击方式**里选）：

#### ① 「点击图片区域」（默认）—— 在识别到的区域内随机

程序先做模板匹配 / OCR，得到目标在屏幕上的**矩形区域** `(x, y, w, h)`，然后：

```
中心点   cx = x + w/2      cy = y + h/2
抖动范围 range_x = w/3     range_y = h/3
实际点   X ∈ [cx - w/3, cx + w/3]  ∩  区域范围
         Y ∈ [cy - h/3, cy + h/3]  ∩  区域范围
```

也就是：**在识别区域「中间约三分之二」的范围内均匀随机取点。**

举例 —— 识别到的区域是 `x=600, y=400, w=138, h=61`：

| | 计算 | 结果 |
| --- | --- | --- |
| 中心 | 600+69 / 400+30 | (669, 430) |
| 抖动范围 | 138/3=46, 61/3=20 | ±46, ±20 |
| **实际点击落在** | X ∈ [623, 715]，Y ∈ [410, 450] | 区域内 92×40 的一块 |

> **为什么不是整个区域都随机？** 因为识别区域往往**比目标按钮大一圈**（模板会把周围背景也框进去）。
> 如果允许点到区域最边缘，就可能点到相邻的按钮或空白处。收窄到中间 2/3 是「既随机又点得准」的折中。
>
> 上面的数字是**实测统计**（采样 400 次），不是推算。

#### ② 「点击自定义区域」—— 在整块指定区域内随机

你自己填一个区域 `[x1, x2, y1, y2]`（**注意是「两个区间」，不是「左,上,宽,高」**），程序在这个范围内随机：

```
X ∈ [x1, x2] 的整数
Y ∈ [y1, y2] 的整数
```

例如填 `[100, 200, 300, 400]` → 点击点落在 `X∈[100,200]`、`Y∈[300,400]` 的整个矩形内。

> 这种方式的随机范围**完全由你决定**，和识别结果无关。适合「位置基本固定、只想避免每次都点同一个像素」的场景。
> 如果 `x1 == x2` 且 `y1 == y2`，就等于**固定点点击**（没有随机）。

### 2.2 两种方式怎么选

| 场景 | 建议 |
| --- | --- |
| 点按钮、开关、页签等**有图案**的目标 | 「点击图片区域」——让识别决定位置，随机只在中间 2/3 抖动，最稳 |
| 目标**没有稳定图案**，或位置基本固定 | 「点击自定义区域」，自己框一个范围 |
| 需要**绝对精确**点某一点 | 「点击自定义区域」并让 x1=x2、y1=y2 |

## 三、随机等待

### 3.1 在哪配

**设置页 → 编辑模式和图像 → 选中一张图 → 编辑图像配置 → 点击区域设置 → 点击后随机等待(秒)**

```
点击后随机等待(秒):  [0.8] ~ [5.0]   （默认 0.8~5，留空按默认）
```

**这是按图配置的**，每张图可以不一样。比如：

| 图片 | 建议等待 | 原因 |
| --- | --- | --- |
| 普通点击按钮 | `0.8~5`（默认） | 常规节奏 |
| 需要等界面响应的操作 | `0.5 ~ 1.5` | 等动画播完 |
| 结算/加载这类长驻界面 | 可调大，如 `1 ~ 3` | 界面本身就要停留 |

### 3.2 默认值与填写规则

| 情况 | 行为 |
| --- | --- |
| **两个框都留空** | 用默认 `0.8~5` 秒，并且**不写进配置文件**（保持配置干净） |
| **只填一个** | 另一个按默认补。例如只填最短 `2` → 实际是 `2 ~ 5` |
| **写反了**（如 `8` 和 `1`） | **自动交换**成 `1 ~ 8`，不会报错卡住你 |
| **填负数** | 会被拒绝并提示 |

### 3.3 等待是怎么执行的

```
点击 → 在 [最短, 最长] 内均匀取一个随机秒数 → 等待 → 再进行下一步识别
```

三个细节值得知道 → 现在是**四个**：

1. **这一项就是程序的主节奏。** 过去主循环末尾还写死了一段 `1.0~2.0` 秒的随机休眠，
   对所有图一视同仁、也改不了；**现已移除** —— 两次识别之间的间隔完全由「按图配置的
   点击后随机等待」决定。想让某张图之后停久一点，直接改这张图的值即可。
2. **等待发生在「点击之后」**，不是点击之前。因为紧接着就去识别下一张图，效果上等于
   「下一张图之前等一会儿」。每轮的第一张图之前没有这个等待（那时还没点过任何东西）。
3. **暂停时不计入等待时间**。如果你中途暂停了挑战，暂停的那段时间不算在随机等待里 ——
   恢复后剩下的等待继续走完。停止挑战则**立刻中断**等待。
4. **每次实际等待的秒数都会写进日志**，方便事后核对（见下一节）。

> 随机等待加在**点击**和**滑动**之后（两者都会进入下一轮识别）；**纯等待（wait）**动作不在其列 ——
> 它本身就带时长参数（「时长(秒)」），可以直接填。

> **一张图都没匹配到时**，程序仍会做一次节流（默认 `0.7~2` 秒），
> 否则等界面时会全速截图空转。这段是兜底，与按图配置无关。

### 3.4 日志长什么样

**挑战开始时**会先打印默认区间 + 哪些图单独配过：

```
点击后随机等待：默认 0.8~5 秒（节奏由它接管；未匹配到任何图时另有 0.7~2 秒节流）；已单独配置的图：tanshi, jieshu
```

（如果没有任何图单独配置，会提示「可在 编辑图像配置 里按图修改」）

**每次点击后**：

```
后台点击 (655, 420)
点击后随机等待 2.64 秒（任务 tanshi 区间 1~3）
```

注意括号里的 **`任务 tanshi 区间 1~3`** —— 一眼就能看出这次用的是**哪张图**的配置，也就确认了「按图配置」确实生效。

走「通用挑战」的非管道模式（魂王、觉醒、爬塔、业原火、御灵、契灵探查、结界突破、灵染等）日志口径一致，
只是把「任务」写成「图」：

```
后台点击 (655, 420)
点击后随机等待 0.86 秒（图 tiaozhan 区间 0.8~5）
```

如果实际等待远大于目标（比如中途被暂停过），会再补一条：

```
实际等待 6.20 秒（含暂停时间），目标 2.64 秒
```

中途被停止/中断时：

```
等待被中断（已等待 1.03 秒，挑战已停止）
```

## 四、怎么确认真的生效了（看日志）

不用猜，看日志就行。**判断「随机点击」是否生效，看点击坐标是否会变：**

```
后台点击 (655, 420)
后台点击 (623, 441)
后台点击 (708, 415)
```

坐标每次都不同 → 随机点击生效。**前提是同一张图被连续点了几次**；如果只点一次，自然只看到一个坐标。

**判断「随机等待」是否生效，看等待秒数是否在区间内浮动：**

```
点击后随机等待 0.63 秒（任务 xxx 区间 0.8~5）
点击后随机等待 2.64 秒（任务 xxx 区间 0.8~5）
点击后随机等待 4.83 秒（任务 xxx 区间 0.8~5）
```

只要这些秒数**都不一样**且落在区间内，就是生效的。

## 五、调参建议

### 随机等待

| 目标 | 怎么调 |
| --- | --- |
| 更接近人工（更保守） | 区间拉大，如 `0.5 ~ 6`；但整体耗时会明显变长 |
| 想快一点 | 区间收窄，如 `0.2 ~ 0.8`；注意别低于界面响应时间，否则会点空 |
| 关键界面老点不中 | 把该图的**最短**调大一点（如 `1 ~ 2`），给它足够时间响应 |

> 一个常见误区：**把等待调到 0 想更快**。结果是下一步识别在界面还没刷新时就执行了，
> 反而更容易出错、重试更多，总耗时更久。**宁可留一点余量。**

### 随机点击

| 目标 | 怎么调 |
| --- | --- |
| 更自然 | 用「点击图片区域」，把模板裁得**紧一点**（只框按钮本身，少带背景） |
| 点不准 / 点到旁边 | 换成「点击自定义区域」，手动框一个**小的**安全范围 |
| 完全固定 | 「点击自定义区域」且 `x1=x2, y1=y2` |

## 六、常见问题

**Q：等待秒数每次都在变，是正常的吗？**
A：正常，这正是它要做的。固定不变才是没生效。

**Q：为什么随机等待的日志里秒数和区间对不上（比如区间 0.8~5，实际等 2.64）？**
A：对得上 —— 2.64 就在 0.8~5 之间。日志打的是**本次实际等待值**，区间是**取值范围**。

**Q：我把等待设成 0.8~5，感觉整体很慢。**
A：默认区间偏保守（平均约 2.65 秒/次）。想快就收窄区间，比如 `0.2 ~ 1.0`（平均约 0.6 秒/次）。
但别设成 0。

**Q：改了「点击后随机等待」，但日志没变化？**
A：改动需要**重启程序**才生效（配置在启动时读取）。另外注意确认改的是**当前模式**里那张图 ——
配置是按图存的。

**Q：随机点击会不会点错按钮？**
A：不会跑到区域外 —— 计算时会把范围**夹回**识别区域内（`max/min` 限制），
而且只在中间 2/3 抖动，留了安全边距。若仍点不准，多半是**模板框得太大**，把周围按钮也框进去了，
重截一个更紧的模板即可。

## 附：一句话总结

- **随机点击** = 每次在目标区域内换一个点（识别区域取中间 2/3；自定义区域按你给的范围）。
- **随机等待** = 每次点击后等一个按图配置的随机时长（默认 0.8~5 秒），**并且它就是两次识别之间的全部节奏** ——
  主循环里原来写死的 `1.0~2.0` 秒已移除；暂停不计入，日志可见。
- 两者都在**编辑图像配置**里按图设置，改完需**重启程序**。
