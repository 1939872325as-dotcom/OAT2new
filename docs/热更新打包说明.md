# OAT 热更新打包指南（改代码不用重新编译）

> 目标：把 `OAT.exe` 从「业务代码全编译进去」改成「启动器 + 磁盘源码」，
> 之后**修改 `OAT/**.py` 只需重启程序即可生效**，不必再用 Nuitka 编译。

---

## 一、为什么原来的 exe 改了源码不生效

Nuitka `--standalone` 会把 `OAT/**` 全部编译进 exe。运行时 Nuitka 的**冻结导入器**
在 `sys.path` **之前**生效，所以磁盘上的 `.py` 被完全忽略。

> 实证：把 `OAT/` 文件夹整个改名移走，旧 exe 行为**完全不变**。
> 再用字节搜索旧 exe，能搜到 `OAT` 内部代码里的中文日志文案 —— 代码确实在里面。

**结论：单纯在 `main.py` 里加 `sys.path.insert` 是没用的，必须让 Nuitka 别编译 OAT 包。**

---

## 二、改造后的架构

```
OAT.exe                    启动器：第三方依赖已编入，业务代码不在里面
python312.dll / *.pyd / PyQt6/ / cv2/ / numpy/ / rapidocr/ ...  ← 第三方依赖
OAT/                       ← 【热更新目标】业务源码，明文 .py
    app/ core/ config/ pipeline/ source/ tools/ utils/
rapidocr/                  rapidocr 运行时数据（default_models.yaml + models/*.onnx）
platforms/                 Qt 平台插件（qwindows.dll）
logs/                      运行日志
```

**分工**：第三方库（体积大、极少变）编译进 exe；业务逻辑（天天改）留在磁盘。

## 三、需要改的两个文件

### 1. `main.py` —— 让磁盘源码优先

```python
def _prefer_disk_source() -> str:
    if getattr(sys, "frozen", False) or "__compiled__" in globals():
        base = os.path.dirname(os.path.abspath(sys.executable))
    else:
        base = os.path.dirname(os.path.abspath(__file__))
    if os.path.isdir(os.path.join(base, "OAT")):
        while base in sys.path:
            sys.path.remove(base)
        sys.path.insert(0, base)
    return base

SOURCE_DIR = _prefer_disk_source()
```

`OAT/` 不存在时自动回退到 exe 内置代码，不会崩。

### 2. `_nuitka_deps.py` —— 补回被 `--nofollow-import-to` 跳过的第三方依赖

因为 OAT 不再被扫描，Nuitka 就发现不了 OAT 用到的 PyQt6/cv2/rapidocr 等，
所以要把它们显式 import 一次让 Nuitka 收集。

> ⚠️ **这些 import 必须写在函数体内、且永不调用。**
> 写在模块顶层会让程序一启动就抢先 import PyQt6/qfluentwidgets/rapidocr/pythoncom，
> 打乱 Qt 与 COM 的初始化顺序 —— 实测直接导致
> `Nuitka: A segmentation fault has occurred` 段错误。
> 放在函数里 Nuitka 照样能静态收集到，但运行时零副作用。

## 四、编译命令（关键参数）

```bat
python -m nuitka --standalone ^
  --windows-console-mode=attach ^
  --nofollow-import-to=OAT ^
  --no-deployment-flag=excluded-module-usage ^
  --include-package-data=rapidocr ^
  --enable-plugin=pyqt6 ^
  --windows-icon-from-ico=OAT/tools/uiResources/icon.ico ^
  --include-data-dir=OAT/tools/uiResources=OAT/tools/uiResources ^
  --output-filename=OAT ^
  main.py
```

### 三个参数各自的作用（**少一个都不行**）

| 参数 | 作用 | 漏了会怎样 |
|---|---|---|
| `--nofollow-import-to=OAT` | 不把 OAT 编进 exe → 磁盘源码才有机会被加载 | 磁盘源码被忽略，退回旧行为 |
| `--no-deployment-flag=excluded-module-usage` | **关掉 Nuitka 的"被排除模块禁止运行时导入"安全机制** | 启动即报 `ImportError: Module 'OAT' was actively excluded from Nuitka compilation` |
| `--include-package-data=rapidocr` | 收集 rapidocr 的 `default_models.yaml` 和 `models/*.onnx` | 启动时报 `FileNotFoundError: rapidocr\default_models.yaml` |

> `--nofollow-import-to` 与 `--no-deployment-flag=excluded-module-usage` 是**成对**的：
> 前者说"别编译"，后者说"允许它运行时再导入"。这是 Nuitka 防漏打包的设计，
> 热更新正好要突破它。

### 编译环境（实测可用）

| 组件 | 版本 | 备注 |
|---|---|---|
| Python | **3.12.10** | 与 exe 内 `python312.dll` 一致 |
| Nuitka | 4.2.2 | 首次编译会自动下载 MinGW-w64 gcc 15.2.0 到 `%LOCALAPPDATA%\Nuitka\Nuitka\Cache` |
| 编译耗时 | 约 15 分钟 | 之后增量编译会快些 |

**`requirements.txt` 有三处错/漏，必须手动修正：**

1. `numpy == 2.2.6` **与** `opencv-python == 4.8.0.74` **不兼容**（cv2 4.8 按 numpy 1.x 编译，
   numpy 2.x 移除了 `numpy.core`）→ 实际应装 **`numpy==1.26.4`**。
   佐证：作者发布的构建目录里存在 `numpy/core/`（1.x 标志）而不是 `numpy/_core/`。
2. 漏了 **`loguru`**（`OAT/utils/logging.py` 依赖它）→ 不装则 `ModuleNotFoundError: loguru`。
3. 漏了 **`qfluentwidgets`**（设置页 UI 组件库）→ 不装则界面无法启动。

```bat
pip install -r requirements.txt
pip install "numpy==1.26.4" loguru PyQt6-Fluent-Widgets "rapidocr==3.7.0" onnxruntime nuitka
```

## 五、部署时必须一并拷贝的"运行时数据"

新构建的 `main.dist/` **不含**这些（它们不在 exe 里，而是运行时从磁盘读）：

| 路径 | 来源 | 说明 |
|---|---|---|
| `OAT/` | 源码树 | 业务源码（热更新目标） |
| `OAT/source/**` | 源码树 + **你的自定义模式** | `mode.json`、各模式 `config.json`、模板图；**你的 `PVE/`、`最新版本活动` 必须覆盖过去** |
| `OAT/tools/settings.json` | 你的旧目录 | 你的设置（抓屏模式、阈值、MuMu 路径…） |
| `OAT/config/update.json` | 你的旧目录 | 忽略更新列表 |
| `rapidocr/` | site-packages | `default_models.yaml` + `models/*.onnx` |
| `platforms/` | PyQt6 插件目录 | `qwindows.dll` |
| `logs/` | 自动生成 | — |

> 反向提示：**部署新版本时不要整目录覆盖你的 `OAT/source/`**，否则自定义模式会被上游版本冲掉。

## 六、验证方法

### 1. 确认业务代码没被编进 exe（字节搜索）

```powershell
$b = [IO.File]::ReadAllBytes('OAT.exe')
$L = [Text.Encoding]::GetEncoding(28591); $hay = $L.GetString($b)
$needle = $L.GetString([Text.Encoding]::UTF8.GetBytes('_outer_size_for_client'))
if ($hay.IndexOf($needle) -ge 0) { 'FOUND - 仍被编译进 exe' } else { 'absent - 已外部化（正确）' }
```

同理应能在 exe 里搜到 `PyQt6` / `rapidocr`（第三方依赖仍在内）。

### 2. 证明"改磁盘源码即生效"

在 `OAT/core/app_launcher.py` 的 `window.show()` 后面临时加一行：

```python
        logger.info('HOTPROBE-OK')
```

删掉 `OAT/**/__pycache__`，重启 `OAT.exe`，然后在 `logs/log_<日期>.log` 里搜 `HOTPROBE-OK`。
**能搜到即证明热更新生效**（实测已验证通过）。验完记得把那行删掉。

## 六点五、必踩的坑：VC++ 运行时 DLL 版本错配导致闪退

**症状**：程序能启动、界面正常，但**一进入需要 OCR 的流程就闪退**（无 Python 报错，日志停在
`正在初始化OCR引擎`）。Windows 事件日志：

```
错误应用程序名称: OAT.exe
错误模块名称: MSVCP140.dll，版本: 14.26.28720.3
异常代码: 0xc0000005
错误模块路径: ...\OAT-hot\MSVCP140.dll
```

**根因**：Nuitka 会从 **PyQt6 的 bin 目录**收集 VC 运行时，而那里是 **14.26（VS2019 早期版）**；
而 `VCRUNTIME140.dll` 可能被更新成 **14.42**。两者**不配套**——新的 vcruntime 调用旧 msvcp 里
不存在的符号，一旦某个库（这里是 onnxruntime）真正加载，就访问违例崩溃。

对照表（本次实测）：

| DLL | 崩溃时 | 修复后 |
|---|---|---|
| `MSVCP140.dll` | 14.26.28720.3（来自 PyQt6） | **14.44.35211.0** |
| `VCRUNTIME140.dll` | 14.42.34438.0 | **14.44.35211.0** |

**修复**：把 exe 目录下这 6 个 DLL 统一换成**系统里配套的那一套**：

```powershell
$vc = 'MSVCP140.dll','MSVCP140_1.dll','MSVCP140_2.dll','VCRUNTIME140.dll','VCRUNTIME140_1.dll','CONCRT140.dll'
foreach ($f in $vc) { Copy-Item "C:\Windows\System32\$f" ".\$f" -Force }
```

**验证**（不用跑游戏，直接在 exe 里试 OCR 初始化）：在 `OAT/core/app_launcher.py` 的
`window.show()` 后临时插入

```python
        try:
            logger.info('OCRPROBE-START')
            from OAT.utils.OCRService import ocr_service
            ocr_service.ocr_manager._init_reader()
            logger.info('OCRPROBE-OK reader=' + str(ocr_service.ocr_manager.reader is not None))
        except Exception as _e:
            logger.info('OCRPROBE-FAIL ' + repr(_e))
```

重启后日志出现 `OCRPROBE-OK reader=True` 即说明 OCR 链路已通。**验完删掉这段。**

> 提示：这个坑和热更新无关，**全编译版本同样会踩**。只要目标机器缺 VC++ 2015-2022 运行库，
> 或 Nuitka 收进了 PyQt6 自带的旧版运行时，就会复现。打包后建议固定检查一次这 6 个 DLL 的版本。

## 七、取舍与限制

| | 全编译（旧） | 热更新（新） |
|---|---|---|
| 改 `OAT/**.py` | 重新编译 ~15 分钟 | **重启程序即生效** |
| 改第三方依赖 / `main.py` 启动逻辑 | 重新编译 | **需要重新编译** |
| exe 体积 | 121 MB | **63.9 MB** |
| 启动速度 | 略快 | 略慢（首次需生成 `.pyc`） |
| 源码可见性 | 编译后不易读 | **明文可见** |

**限制**：

- 只有 `OAT/` 下的改动是热更新；`main.py`、`_nuitka_deps.py`、依赖版本变更仍需重新编译。
- 首次启动会把 `.py` 编译成 `__pycache__` 里的 `.pyc`，之后启动变快。**改完源码不需要手动清缓存**（Python 按 mtime 自动失效），只有在时钟异常或想强制刷新时才需要删。
- 由于源码是明文，若你要对外分发且希望隐藏实现，应改用全编译版本。
- `--windows-console-mode=attach`：从控制台启动时会附加输出便于排错，双击启动则无控制台窗口。
