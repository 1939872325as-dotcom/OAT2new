# OAT 新手操作指引 —— 模式与图片编辑

> 面向第一次自己加模式/换图的人。基于 `main`(v2.3.4)真实源码 + 你本机已有的实际配置样例。
> 编辑器自带一份「查看使用说明」弹窗(`edit_mode_and_img.py:1485`),本文把它展开讲透并补上它没说的坑。

---

## 一、先搞懂这四个东西的关系

```
OAT/source/mode.json                 ← 目录:哪个模式名 → 哪个文件夹
        │  "业原火": "yeyuanhuo"
        ▼
OAT/source/yeyuanhuo/                ← 这个模式的家
        ├── config.json              ← 说明书:有哪些图、每张图什么意思
        ├── tiaozhan.png             ← 模板图:在游戏里截下来的小图
        ├── jieshu.png
        └── ...
```

一句话:**`mode.json` 负责"下拉框里能不能选到",`config.json` 负责"选到之后怎么打",`png` 是"拿什么去比"**。

三者只要有一处不对,表现都是"选不了模式"或"识别不到图":

| 现象 | 缺的是哪一环 |
|---|---|
| 下拉里没有你新建的模式 | `mode.json` 没登记(或没重启) |
| 日志 `不支持的模式: XXX` | 同上 |
| 下拉能选,但点开始没反应 | 模式目录不存在 / 目录名对不上 |
| 能跑,但一直在原地空转、日志不显示"已开始挑战" | 图没截对,或 `是否是挑战开始` 没勾 |

## 二、编辑器在哪、怎么开

**设置页 → 「编辑模式和图像」卡片** → 弹出 `ModeEditorDialog`(`main_window.py:1204-1207`;
卡片文案见 `settings_page.py:158-159`,提示为「编辑游戏模式的图像配置」)。

窗口里左边是模式树,按钮分两组(`edit_mode_and_img.py:846-898`):

| 组 | 按钮 | 作用 |
|---|---|---|
| 模式管理 | 添加模式 / 添加子模式 / 删除模式 / 重命名模式 | 改 `mode.json` |
| 图像管理 | 添加图像 / 删除图像 / 替换图片 / 编辑图像配置 | 改目录里的 png + `config.json` |
| | 复制图片配置 / 粘贴图片配置(快捷键 **Ctrl+C / Ctrl+V**) | 图片+配置一起复制到别的模式 |
| | 查看使用说明 | 官方说明弹窗 |
| | **保存 / 取消** | **不点「保存」前面全白干** |

> **跨模式复用同一张图**:在图像列表里选中图 → **Ctrl+C**(或右键「复制图片配置」)
> → 左边模式树选中目标模式 → **Ctrl+V**(或右键「粘贴图片配置」)。
> 图片文件、`image_paths`、`pipeline.tasks` 会一起复制,OCR/点击区域/动作/等待时间等配置全部保留;
> 目标里重名时自动改名为 `xxx_copy.png`、`xxx_copy2.png`…,不会覆盖已有图片。
> 剪贴板是程序内部的,复制后源图即使被改名/删除也能粘贴。

> ⚠️ 新手第一个坑:**改完必须点「保存」**。这个编辑器没有自动保存,点「取消」会全部丢弃。
> 而且保存只写文件,**运行时不会热加载**——`mode.json` 是启动时读入的,所以要**重启程序**才生效。

## 三、截图这一步的新手铁律(最容易翻车)

官方说明里那句红字是重点(`edit_mode_and_img.py:1519`):

> **添加的本地的图片必须在执行窗口检测之后的游戏窗口内截图,否则会导致识别失败。**

为什么?因为**窗口检测会把游戏窗口调整到一个固定尺寸**(设置里的「自定义同步时的窗口大小」,
**默认 1441×812**),而模板匹配是**按像素**比对的。你在别的窗口尺寸下截的图,和实际跑起来的
画面尺寸不一致 → 匹配必失败。

所以正确顺序是:

1. 游戏/模拟器打开到目标界面;
2. 在 OAT 里点一次**窗口检测**(让它把窗口调成目标尺寸,即设置里显示的宽×高);
3. **保持窗口尺寸不变**,在游戏里截取模板图;
4. 再把图「添加图像」进来。

> **更省事的做法**:直接用新增的「**截图添加 / 截图替换**」按钮 —— 它抓的就是游戏窗口客户区,
> 截出来的尺寸**天然等于识别时用的尺寸**,并会把位置自动填进「OCR搜索区域」。

> **关于“截图时窗口自动变大”**:截图工具本身**不会**调整游戏窗口大小(只有窗口最小化时才恢复)。
> 变大的来源通常是:
> 1. 你刚点过**窗口检测** —— 它会按设置把客户区调到 1441×812(设计如此,保证模板与运行时同尺寸);
> 2. 高 DPI 缩放下,框选遮罩以前会画得比窗口大一圈(110 DPI 时约 +14.6%)。
>    该问题已在 v234.1 修复:遮罩现在按逻辑像素贴合客户区,不会再“放大”。
>
> 只要**截图和运行时的客户区尺寸一致**(日志里 `框选截图：抓到 1441x812` 与识别时
> `截图 812x1441` 对得上),窗口大小就不会导致识别失败。

其他截图要点:

- **只截一小块有辨识度的区域**(按钮、图标、标题文字),别整屏截。整屏图既慢又容易误匹配。
- **PNG 格式**,不要缩放/压缩/二次编辑,直接原样截取。
- **别截会变的东西**:数字、进度条、剩余次数这类每局都变的内容不能当模板。
- **同一个界面里有多个相似按钮时**,要截它们**不同的那部分特征**。
- ⚠️ 分辨率、窗口尺寸、游戏 UI 改版之后,**旧图全部要重截**。

## 四、「编辑图像配置」弹窗逐字段说明

这是新手最懵的地方。窗口长这样(`edit_mode_and_img.py:330-503`):

```
图像名称:  [tiaozhan          ]
路径:      [tiaozhan.png      ]  [浏览…/替换图片]     ← 选图,保存时复制到当前模式目录
           [预览小图]
☐ 是否是挑战开始
消息:      [已开始挑战        ]
☐ 是否全局
下一张图片: [ (下拉,选别的图)  ]
┌ 点击区域设置 ──────────────────────┐
│ 动作类型: [点击/滑动/等待]           │   ← 注意:滑动、等待只在 pipeline 模式生效
│ 自定义区域: [left, top, width, height]│
│ 终点区域:   [...]   时长(秒): [ ]    │   ← 滑动用
└──────────────────────────────────┘
┌ OCR配置 ─────────────────────────┐
│ ☐ 是否启用OCR                      │
│ OCR识别文本: [退治      ]          │
│ OCR识别阈值: [0.8      ]           │
│ OCR搜索区域: [900,1280,500,700]    │   ← 可选,留空=全窗口(同一文字有两处时用它)
│ OCR识别后的操作: [点击文字所在区域 ▾] │
└──────────────────────────────────┘
```

### 字段对照表

| 界面名称 | JSON 字段 | 什么意思 | 怎么填 | 填错的后果 |
|---|---|---|---|---|
| 图像名称 | (键名) | 这张图在配置里的名字 | 英文,有含义 | — |
| 路径 | `path` | 图片文件名 | 一般同图像名称 | 文件不存在 → 日志报"缺少素材" |
| (浏览…/替换图片) | — | 从资源管理器选图,**保存时复制进模式目录** | — | — |
| **是否是挑战开始** | `is_challenge_start` | **找到这张图 = 完成一次挑战**,进度 +1 | 只给"进入战斗那一张"勾 | **没勾 → 进度永远不加,挑战次数不动** |
| 消息 | `message` | 识别到时在日志里打印的字 | 中文提示,如"已开始挑战" | 无影响,只影响可读性 |
| **是否全局** | `is_global` | 每轮**先于**主流程检查(用于弹窗) | 只给"意外弹窗"勾,如御魂爆仓、好友协助 | 乱勾 → 干扰正常流程 |
| 下一张图片 | `next_image` | 找到这张之后,**下一步只找它** | 用于固定流程串链 | 见第五节 |
| 动作类型 | `action_type` | 点击 / 滑动 / 等待 | 老模式只有"点击" | **老模式下选滑动/等待无效** |
| 自定义区域 | `click_area` + `click_type:"coordinate"` | 不点图,改点指定坐标 `[左, 上, 宽, 高]` | 点击位置固定时用 | 区域写错 → 点偏 |
| 终点区域 / 时长 | `end_area` / `duration` | 滑动用 | pipeline 模式 | — |
| 是否启用OCR | `ocr_enabled` | 找不到图时用**文字**兜底 | 图不稳定时才开 | 开着会变慢 |
| OCR识别文本 | `ocr_target_text` | 要在画面里找到的文字 | **必须和游戏里显示的完全一致** | 写错 → 一直识别不到 |
| OCR识别阈值 | `ocr_confidence_threshold` | 文字置信度门槛,默认 0.8 | 一般不用改 | 调太低 → 误识别 |
| **OCR搜索区域** | `ocr_region` | 只在这个范围内找文字,格式 `[x1, x2, y1, y2]` | 同一画面有两处相同文字时用 | 填错 → 找不到文字 |
| OCR识别后的操作 | `ocr_action` | 「点击文字所在区域」或「点击点击区域设置的区域」 | 默认第一个 | — |

### 关于"点击区域设置"的两种模式(官方原文)

- **点击图片区域**:点击识别到的图像区域(即点击模板图匹配到的那块)。
- **点击自定义区域**:点击指定的坐标区域,格式为 `[left, top, width, height]`。

> 典型场景:某个按钮**样子会变**(所以没法当模板),但位置固定 → 用一张**别处的稳定图**做触发,
> 再把「点击自定义区域」指到那个按钮的坐标上。

### 关于 OCR(官方原文重点)

> OCR 是文字识别技术……**会增加识别时间,建议在图像识别无法识别到时使用 OCR**。

也就是:**优先用图,OCR 只做兜底**。OCR 文本一定要填游戏里那一帧**真实显示**的文字
(你之前 PVE 里填的「退治」「点击屏幕继续」就是这个用法)。

### ⚠️ 一个界面里有两处相同文字怎么办(点错位置的根因)

这是 OCR 最容易翻车的场景:比如页面上有两个"挑战",程序点了另一个,位置和你预期不同。

**机制**:OCR 识别出的文字会按"自上而下、自左而右"排列,程序在**多个命中里只挑一个**。如果不能确定
挑哪个,它就会挑顺序里靠前的那个——而你要的可能是下面那个。

**做法:填「OCR搜索区域」**,把另一处相同文字排除在搜索范围外:

```
OCR搜索区域: [900, 1280, 500, 700]
```

格式是 **`[x1, x2, y1, y2]`**——x 的范围和 y 的范围,**不是** `[左, 上, 宽, 高]`。

> 注意:编辑器里那个官方「查看使用说明」把这个格式写成了"`[left, top, width, height]`",**那是错的**。
> 代码里 `OnmyojiAuto.py` 是 `x1, x2, y1, y2 = click_area` 这样解包的,所以真实的格式是
> **两段范围**。文档里其它地方提到 `click_area` 也是同一个格式。
>
> 顺便:因为区域必须是"x1≤x2、y1≤y2",所以像 `[500, 900, 300, 700]` 这种(把范围写反了)会被
> 编辑器拒掉并提示格式不对 —— 提示是正常的,不是你写错了别的。

**怎么判断到底命中了几处**:日志里会打印候选清单,直接看坐标就能知道该收窄哪里:

```
OCR: '挑战' 命中 2 处，选用置信度最高的一处（0.9987）
    候选1: '挑战' conf=0.9987 x: 1024-1108  y: 55-85   <== 选用
    候选2: '挑战' conf=0.9961 x: 1024-1108  y: 640-670
```

看到"命中 2 处"就说明该填 `ocr_region` 了。留空则是全窗口(和以前一样)。

## 五、两个必须搞懂的概念

### 1. `next_image`(下一张图片)= 串链,不是流程编排

它的含义是"**找到 A 之后,下一步只去找 B**"。形成链条后,识别范围被收窄,更快也更准。

- 老模式的典型用法(`jiejietupo/config.json`):`找勋章图 → next: jingong(进攻)`。
- **超时保护**:链上的下一张图 **15 秒**内没找到,会自动退回"全图扫描"模式
  (`common_challenge.py` 里 `NEXT_IMAGE_TIMEOUT = 15`,日志会打「识别超时」)。
- **别把链串死**:链尾那张图要留空(`""`),否则会一直等它。

### 2. `is_global`(是否全局)= 意外弹窗兜底

全局图会在**每轮主流程之前**先检查一遍,命中就点掉,然后继续。适合:

- 御魂爆仓提示
- "好友请求协助"弹窗(点拒绝)

反例:把"结束""结算"这类**正常流程图**勾成全局,会打乱流程。

## 六、老模式 vs 新模式:两套引擎,字段含义不完全一样

这是新手最容易困惑又最难自查的一点。`source/__init__.py:80` 是分岔点:

| | 老模式(魂土/业原火/觉醒/结界突破…) | 新模式/自定义(如你建的 PVE) |
|---|---|---|
| config.json 里有什么 | 只有 `image_paths` | 有 `pipeline` |
| 走的引擎 | `common_challenge`(通用挑战) | `create_and_run_pipeline`(MAA 风格管道) |
| 支持的动作 | **只有点击** | 点击 / 滑动 / 等待 |
| 编辑器的"动作类型"下拉 | 选了也不生效 | 生效 |

判断方法:打开那个模式的 `config.json`,**看到 `"pipeline"` 就是新模式**。

> 你之前给「最新版本活动」建的 `source/PVE/config.json` 就是新模式(里面 `image_paths` 和
> `pipeline` 两段都有,编辑器会自动同步这两段)。

## 七、新手最常踩的 10 个坑

| # | 症状 | 原因 | 改法 |
|---|---|---|---|
| 1 | 下拉里选不到新模式 | `mode.json` 没登记 | 用编辑器「添加模式」,或手改 `mode.json` 后**重启** |
| 2 | 改完没反应 | 没点「保存」,或没重启 | 点保存 + 重启 |
| 3 | 一直识别不到图 | 图不是**窗口检测之后**截的,尺寸对不上 | 重新按第三节顺序截图 |
| 4 | 一直在原地打转,进度不动 | 「是否是挑战开始」没勾 | 给进战斗那张图勾上 |
| 5 | 卡在某个界面反复重试 | 上一张图的 `下一张图片` 指错了,或链尾没留空 | 检查 `next_image` 链 |
| 6 | 弹窗来了不处理,卡住 | 弹窗图没勾「是否全局」 | 给弹窗图勾上「是否全局」 |
| 7 | 点偏了 | 「点击自定义区域」坐标写错 | 区域是 `[左, 上, 宽, 高]`,不是右下坐标 |
| 8 | 选了"滑动"没滑动 | 老模式只支持点击 | 见第六节 |
| 9 | OCR 识别不到文字 | 文本和游戏实际显示不一致(多字/少字/繁简) | 照游戏原样填 |
| 10 | 目录名写中文/带空格 | 官方要求:目录名必须英文、数字或下划线 | 改名 + 同步改 `mode.json` |
| 11 | 两个相同文字,点了另一个 | OCR 在多个命中里取了顺序靠前的那个 | 填「OCR搜索区域」,并看日志里的"命中 N 处" |
| 12 | 日志说"挑战完成"但游戏没动 | 点击没送达(句柄失效)/坐标算不出来 / 识别"命中"了但框无效 | 看日志有没有 `后台点击 (x, y)`;若看到 `无法确定点击坐标`、`窗口句柄无效` 就是这两类原因 |

## 八、从零加一个模式(完整流程)

以"给新活动加个模式"为例:

1. **打开编辑器**(设置页 → 「编辑模式和图像」)→ 点「添加模式」→ 填模式名(如"新活动")和目录名(英文,如 `xindehuodong`)→ 点「保存」→ **重启程序** → 确认下拉里能选到。
2. **窗口检测**:进游戏到该活动界面,在 OAT 里点窗口检测/刷新窗口。
3. **在游戏里截图**,把关键按钮/图标一个个截下来(保持窗口尺寸不变)。
4. **加图**:选中该模式 → 「添加图像」逐张加入 → 每张都点「编辑图像配置」填好含义:
   - 进战斗那一张:`是否是挑战开始` ✔ + `消息` 填"已开始挑战"
   - 战斗结束/结算那几张:不勾,可用 `下一张图片` 串起来
   - 意外弹窗那张:`是否全局` ✔
5. **保存** → 退出编辑器 → **重启程序**(让 `mode.json` 生效)。
6. **试跑**:开 1 次挑战,盯日志看:
   - 有没有 `已预加载 N 张图像模板`;
   - 有没有按预期打 `消息` 里的字;
   - 有没有 `还剩 X 次挑战` 出现(出现才说明 `is_challenge_start` 生效了)。

## 九、不想用编辑器?手改的等价写法

`config.json` 就是纯 JSON,手改等价(改完重启或下一轮生效):

```json
{
  "image_paths": {
    "tiaozhan": {
      "path": "tiaozhan.png",
      "message": "已开始挑战",
      "is_challenge_start": true,
      "is_global": false,
      "next_image": "",
      "click_type": "image",
      "ocr_enabled": false,
      "ocr_target_text": "",
      "ocr_confidence_threshold": 0.8
    },
    "baocang": {
      "path": "baocang.png",
      "message": "御魂爆仓",
      "is_global": true
    }
  }
}
```

**只有 `path` 是必填**,其余都有默认值(官方教程 `OAT/source/自定义配置教程.txt` 的原话:
「其中,is_challenge_start 和 message 是可以不写的,而 path 是必须写的」)。

`mode.json` 手改:

```json
{
  "请选择模式": "",
  "单模式示例": "yeyuanhuo",
  "有子模式的示例": { "default": "pata", "门票": "pata", "体力": "pata_tili" }
}
```

- 单模式 → 直接写目录名;
- 有子模式 → 用大括号,`default` 是默认子模式,其余键是**下拉里显示的中文名**,值是目录名。

## 十、一句话总结

- 四件套:`mode.json`(能不能选到)→ 目录 → `config.json`(怎么打)→ png(拿什么比)。
- 新手三条铁律:**图必须在窗口检测之后截**、**进战斗那张要勾「是否是挑战开始」**、**改完要点保存并重启**。
- 字段里真正会"决定成败"的只有四个:`path`、`is_challenge_start`、`is_global`、`next_image`;
  OCR 只在图不稳定时才开。
- 老模式只支持点击;要"滑动/等待"必须走 `pipeline` 模式(第六节)。
